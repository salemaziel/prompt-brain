# Claude Fable 5.1

## Reasoning / Thinking
- Type: **adaptive, always on**. Omit `thinking` or send `{type: "adaptive"}`; `{type: "disabled"}` and `{type: "enabled", budget_tokens: N}` both return 400 — `disabled` at **every** effort level (Opus 5 still accepts it up to `high`).
- Depth is controlled exclusively via `output_config.effort` (`low | medium | high | xhigh | max`), default `high`. Interleaved thinking runs automatically, without beta headers.
- `thinking.display` default `"omitted"` (empty thinking blocks), `"summarized"` returns a summary; the raw chain of thought is never returned. New: `display: "updates"` (beta `thinking-display-updates-2026-08-18`) delivers progress notes between tool calls legibly in the progress `thinking` blocks (no `text` block; every non-empty `thinking` block is then a status line), while the reasoning remains hidden.
- **Per-message effort** (beta `mid-conversation-output-config-2026-07-01`): a `role: "system"` message with empty `content` and `output_config.effort` raises/lowers effort mid-conversation **without** invalidating the prompt cache. Takes effect starting from the next user turn.
- **Thinking blocks are bound to the generating model** and are only transferable in one direction: Fable 5.1 reads blocks from Opus 5, Fable 5, Mythos 5, and older models, as well as, on the Claude API, from Opus 5.5 (but not those from Sonnet 5.5); blocks from Fable 5.1 are read only by Fable 5.1 and Mythos 5.1. Non-readable blocks are discarded server-side, do not count toward `input_tokens`, and are not billed — reported as `input_transformations` with `thinking-binding-controls-2026-08-01`, otherwise silently.
- **Editing earlier turns invalidates all subsequent thinking blocks** → 400 with `The block is bound to a different conversation`. Enforced for accounts created on or after August 31, 2026; older accounts only when `thinking.block_binding.prefix_mismatch_behavior` (`"error"` | `"drop_block"`) is set. Triggers: rewriting/removing turns, per-request injected and subsequently deleted reminders, rebuilding `system` or `tools`, changing bytes behind an image/document URL. Harmless: trimming leading thinking blocks from the front, server-side compaction/context editing, moving `cache_control`, changing `effort`.
- Non-default values for `temperature`/`top_p`/`top_k` → 400.

## Prompting Style
- Anthropic says explicitly that existing **Fable 5 prompts run well without changes** — there is no requirement to rephrase, only a handful of behavioral deltas against which individual lines are added.
- **Rerun effort sweep**: start at `high`, test all levels against your own evals. Level names do not correspond to the same amount of thinking across models; `medium` is roughly on par with Fable 5 at lower cost.
- **Keep conversation append-only**: send reminders as turn-scoped system messages (`clear_at: "next_user_message"`, beta `mid-conversation-system-clear-at-2026-08-21`) and leave old copies byte-for-byte in place; modify `system`/`tools` via mid-conversation system messages or `tool_addition`/`tool_removal` rather than rebuilding them.
- **Tool-batching nudge** in implicit agent loops, placed after each `tool_result` block: "First privately list what you need next; then request every item that doesn't depend on another's result in this one response."
- **Grant autonomy explicitly**, otherwise the turn ends with "Next, I'll…" or "Shall I…?". The most effective phrasing according to the documentation: inform the model that no one is watching in real time and clarifying questions will block work; add the rule to check the final paragraph before turn end for unfulfilled commitments.
- **Remove old anti-formatting rules** — they were written for older, over-formatting models and suppress necessary structure here. Similarly, remove "hold all findings for the final response" lines and explicitly request updates instead (opening line, intermediate progress, final recap).
- Against unmarked borrowing from sources: include **a complete example** (user request + correct answer + rationale) in the system prompt, not just a rule.
- Add a scope rule against unprompted fixes and test sprawl, as well as a targeted edit rule against whole-file rewrites; for client-side compaction, explicitly list what the summary must preserve.
- Run vision tasks as an agent with a crop/zoom tool (or container with PIL/OpenCV); launch sub-agents asynchronously and let the lead agent continue working.
- **Do not request reasoning in the response text**: prompts, skills, and tool descriptions that prompt the model to write out its thinking/reasoning — verbatim or in a fixed format (`<thinking>`, `<reasoning>`, or scratchpad section before the answer, `reasoning`/`thinking`/`trace` field in JSON output or tool input, reasoning log, reasoning "verbatim"/"in full") — can be rejected with `stop_reason: "refusal"` and `stop_details.category: "reasoning_extraction"`. Instead, request a brief explanation, evidence, or a summary of executed steps; if reasoning itself is needed, keep thinking enabled and read thinking blocks with `display: "summarized"`. This category has no fallback model (modify the prompt rather than resending), and refusals occurring before any output are billed.

## Strengths & Weaknesses (prompt-relevant)
- Strengths (gains over Fable 5, largest at high effort): agentic coding over hour-long sessions (multi-file features, large refactorings/migrations, debugging, code review); knowledge work with documents, spreadsheets, and slides from initial question to finished artifact; multi-step web research; vision on dense charts, filings, and tables nested in PDFs; long-context synthesis across the full 1M window; computer use including recovery after missteps. Multilingual capabilities on par with Fable 5.
- At `low`, according to docs, often competitive with Opus and Sonnet models on cost per task while achieving better scores — measure against these before downgrading to a smaller model.
- Weaknesses / quirks: **fewer parallel tool calls** when subsequent independent reads are only implied (coding harnesses, computer use) — costs turns, not quality; **fewer visible progress texts** in long tool chains, intensified at high effort; fewer search/retrieval calls at `low` (answers more often from memory); **denser prose** (longer sentences, fewer paragraphs); **less formatting** (bold, headers, lists); **unmarked citations** in summaries; **whole-file rewrites** instead of surgical edits.
- At `xhigh`/`max`, the model sometimes drafts long deliverables in thinking first and then rewrites them again → double length, `max_tokens` risk. Doc recommendation: run such requests at `high`, allocate generous `max_tokens`, and append a note that reasoning and answer share a **single** limit.
- Safety classifiers return `stop_reason: "refusal"` (fewer false positives than Fable 5 at launch; vulnerability discovery in source code is permitted). Trigger patterns: compile-check phrasing ("Does this program compile without errors?" → better: "Are there any bugs in this program?"), uncommon programming languages (provide language documentation), Base64 in tool outputs (strip it).

## Output & Format Conventions
- 1M context window as default **and** maximum at standard pricing across the entire window, 128k output tokens. Minimum cacheable prefix: 512 tokens.
- **Forced tool use is discontinued**: `tool_choice: {"type": "any"}` and `{"type": "tool", "name": ...}` return 400 `invalid_request_error` with `tool_choice: type "tool" and "any" are not supported for this model.` — the same check applies to the token-counting endpoint. `auto` (default) and `none` remain unchanged. Replacement: `auto` plus explicit instructions on when the tool applies, combined with `strict: true` or structured outputs.
- No assistant prefill (400).
- Pricing per MTok: input $10, output $50, 5m cache write $12.50, 1h cache write $20, **cache read $0.25** — 0.025× input (Opus 5.5/Sonnet 5.5: 0.05×, remaining Claude models 0.1×); batch $5/$25. Because cache reads are so inexpensive, postponing compaction is worthwhile.
- Tokenizer same as Fable 5 (introduced with Opus 4.7): roughly 30% more tokens for the same text compared to models prior to Opus 4.7.
- Model IDs: Claude API, Google Cloud, Microsoft Foundry, and Claude Platform on AWS `claude-fable-5-1`; Amazon Bedrock `anthropic.claude-fable-5-1`. Status *Active (latest)*, release September 1, 2026, retirement not before September 1, 2027. Reliable knowledge cutoff June 2026.
- `stop_reason: "refusal"` arrives as HTTP 200 with `stop_details` — check before reading `content`. Eligible fallback targets are Claude Opus 4.8 and Claude Opus 5; `fallbacks: "default"` (beta, header `server-side-fallback-2026-07-01`, Claude API only) routes by category, fallback credit refunds the prompt caching costs of the model switch. Refusals before any output are billed since September 24, 2026 if `stop_details.category` is `bio`, `frontier_llm`, or `reasoning_extraction` (previously not billed); in other categories, still not billed. Mid-stream refusals bill input plus already streamed output.
- **30-day retention mandatory**, no ZDR without explicit authorization from Anthropic; Covered Model.
- Content provenance: text outputs carry Anthropic's statistical watermark across all platforms (no extra tokens, no hidden characters); image/video/audio files retrieved via the Files API carry signed C2PA Content Credentials.

## Migration Notes
- **MIGRATING FROM claude-fable-5-1**: Thinking blocks are unreadable for any other model except Mythos 5.1 (including Opus 5.5) and are discarded — reasoning continuity is lost on switch, replace with a summary if necessary. Forced tool use (`tool_choice: any`/`tool`) is supported again on Fable 5, Opus 5, and Opus 4.8; on Opus 5.5 and Sonnet 5.5 still 400 (Haiku 5.5: (unbelegt)); `thinking: {type: "disabled"}` is possible again on Opus 5 and Haiku 5.5 up to effort `high`, on Opus 5.5 400 at every level, on Sonnet 5.5 400 (instead `between_tools`, only up to `high`); the append-only constraint is dropped only for targets without prefix checks — Opus 5.5 and Sonnet 5.5 also enforce it for accounts created on or after August 31, 2026 (cache rationale remains). Remove beta specifics: `display: "updates"`, turn-scoped system messages, `prefix_mismatch_behavior`. Keep per-message effort (`mid-conversation-output-config-2026-07-01`), however, if the target is Opus 5.5, Opus 5, Sonnet 5.5, Haiku 5.5 (each Claude API/Google Cloud; on Bedrock only Opus 5.5), or Mythos 5.1; on Fable 5 it returns 400. Critically review Fable 5.1 compensations — batching nudge, autonomy block, anti-mannered-prose instructions, "more formatting" rule, targeted-edit rule, and citation examples have the opposite effect on models that already over-format or over-cite. The 0.025× cache read rate does not apply (Opus 5.5/Sonnet 5.5: 0.05×, remaining models 0.1×). ZDR eligibility depends on target: Opus 5 and Opus 4.8 are available under ZDR, Fable 5 still requires 30-day retention (otherwise 400).
- **MIGRATING TO claude-fable-5-1**:
  - Specifically **from claude-fable-5**: Swap model ID, remove forced `tool_choice` values, return thinking blocks unmodified (including empty ones), make history append-only and run the three-step check with `thinking-binding-controls-2026-08-01` + `prefix_mismatch_behavior: "drop_block"` while logging `input_transformations`, rerun effort sweep starting at `high`, check agent loops for single-call-per-turn patterns and add the batching nudge, set `display: "updates"` for UI narration.
  - Specifically **from claude-opus-5**: Additionally remove any `thinking: {type: "disabled"}` (returns 400 here at every effort level) and resize `max_tokens` for previously thinking-free routes; text between tool calls is no longer delivered as a `text` block, but as a progress `thinking` block; safety categories are broader than those of Opus 5 (additionally including `bio`; `reasoning_extraction` applies on both models); price doubles to $10/$50; verify ZDR eligibility in advance.
  - Specifically **from claude-opus-4-8**: First complete the Fable 5 migration path (adaptive thinking, remove `budget_tokens`/sampling parameters/prefill, effort, 512-token cache minimum, refusal handling), then apply the Fable 5 delta. Integrations from that era truncate older turns, rebuild `system` per request, or compress client-side — exactly the patterns that subsequently invalidate all thinking blocks here.
