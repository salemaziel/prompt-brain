# GPT-5.6 Sol

## Reasoning / Thinking
- Depth via `reasoning.effort`: `none | low | medium (default) | high | xhigh | max`. Documentation mapping: `none` = latency-critical with no reasoning benefit, `low` = efficient with minimal latency penalty, `high` = "Hard reasoning, complex debugging, deep planning", `xhigh` = "Deep research, asynchronous workflows and agentic tasks", `max` = maximum depth for the most complex tasks.
- Additionally an **independent** switch `reasoning.mode`: `standard` (default) and `pro` — "for difficult tasks that need more model work and can tolerate higher latency and token usage". Pro tokens are billed at standard model rates. Mode and effort must be selected separately.
- `reasoning.context` controls reasoning persistence across turns: `auto | current_turn | all_turns`. GPT-5.6 **defaults to `all_turns`** (earlier models to `current_turn`); `all_turns` renders compatible reasoning items from earlier turns. Summaries are opt-in via `reasoning.summary` (`auto` = most detailed level available); with `store: false`, reasoning items return as `encrypted_content` and can be passed back in follow-up calls.

## Prompting Style
- **Lean prompting is the core rule**: Remove repeated instructions and examples, state each instruction exactly once, expose only relevant tools, keep tool descriptions "concise and precise" (including return fields, types, error behavior). OpenAI measures approximately 10–15% better eval scores with 41–66% fewer tokens and 33–67% lower cost — explicitly labeled as "directional".
- **Set autonomy and approval boundaries explicitly**: Explicitly name safe local actions (reading files, editing code, running tests), require confirmation for "external writes, destructive actions, purchases, or a material expansion of scope". Avoid repeated boilerplate approval phrases; they cause unnecessary clarifying questions.
- **Steer length in two tiers**: Default level of detail via `text.verbosity` (`low | medium | high`), task-specific requirements in the prompt. When asking for brevity, specify what must be retained (doc example: "Lead with the conclusion. Include the evidence needed to support it, any material caveat, and the next action").
- **Tone through concrete writing choices** rather than adjective labels (avoid "friendly").
- **Programmatic Tool Calling (PTC)** for bounded workflows that filter, rank, or aggregate many results. Do not use when a single call suffices, outputs are small, every result changes the next decision, or approvals are needed. Routing instructions specify stage, permitted tools, output schema, and concurrency limits. Multi-agent orchestration is in **Beta** on the Responses API.

## Strengths & Weaknesses (prompt-relevant)
- Positioning: "GPT-5.6 flagship model for complex professional work" — top tier of the GPT-5.6 family (alongside Terra and Luna). OpenAI's current flagship group is GPT-6 (gpt-6-astra, gpt-6.1-sol, gpt-6-luna); GPT-5.6 Sol is listed under "More models", with no deprecation entry. Note on naming: In GPT-6, "Sol" denotes the balanced mid-tier ("Balanced speed, cost, and intelligence"), not the top tier — the bare alias `sol` therefore points to gpt-6.1-sol.
- Strengths: Token efficiency ("flagship-level performance with fewer output tokens"); frontend/design work ("more polished and usable websites and applications", stronger layout and hierarchy decisions); intent inference (infers objective and desired depth of work better from context); agentic multi-turn work via persisted reasoning and PTC.
- Weaknesses: Safeguards can block or refuse requests, occasionally even for legitimate work (primarily security and biology); generation **pauses mid-stream for multiple seconds** while classifiers check synchronously — configure timeouts and streaming accordingly. Pro mode not intended for "routine, latency-sensitive, or high-volume work" and not without measured quality gain. Not supported: Realtime, Assistants, Fine-tuning, Embeddings, image generation/edit, video, audio (speech/transcription/translation) and moderation endpoints, legacy completions (hosted tools `image_generation`/`code_interpreter` remain unaffected).

## Output & Format Conventions
- Context window **1,050,000** tokens, max input **922,000**, max output **128,000**; knowledge cutoff **Feb 16, 2026**; input text + image, output text only.
- Endpoints: `v1/chat/completions`, `v1/responses`, `v1/batch`. Features: streaming, structured_outputs, function_calling, file_search, image_input, web_search, prompt_caching. Hosted tools include web_search, file_search, image_generation, code_interpreter, hosted_shell, apply_patch, skills, computer_use, mcp, tool_search. Control output length via `text.verbosity`.
- Pricing per 1M tokens: Input $4, Cached Input $0.40, Output $20 (since Aug 21, 2026; promotional pricing on model page "at least through November 21, 2026"). Family rule: "Prompts with >272K input tokens are priced at 2x input and 1.5x output for the full request." Prompt caching: Cache writes cost 1.25x the uncached input rate, reads remain discounted — track `cached_tokens` and `cache_write_tokens`, set explicit breakpoints.
- The alias `gpt-5.6` routes to GPT-5.6 Sol; only the single snapshot ID `gpt-5.6-sol` is listed (no dated snapshot).

## Migration Notes
- **MIGRATING FROM gpt-5.6-sol**: Map `reasoning.effort` to the target model's effort ladder (names and levels differ by provider; carry over `none`, `xhigh`, `max` only if documented in the target guide); `reasoning.mode`, `reasoning.context`, and `text.verbosity` are omitted and must be reconstructed as prose instructions. Re-add explicit brevity/verbosity requirements and any removed few-shot examples, as other models infer less from context. Remove PTC / multi-agent routing. Verify the 1.05M token context assumption — target models are usually substantially smaller. To gpt-6-astra: According to OpenAI, "generally better than GPT-5.6 Sol and earlier models at staying coherent during long tasks"; `none` effort is not supported there (→ `low`) — the same applies to gpt-6.1-sol, and for both, tool calling requires the Responses API.
- **MIGRATING TO gpt-5.6-sol**: Official successor for `gpt-5-2025-08-07` and `o3-2025-04-16` (shutdown Dec 11, 2026) as well as `o3-mini-2025-01-31` (shutdown Oct 23, 2026). (1) Keep previous effort level as baseline and additionally test **one level below**. (2) Slim down prompt: Strip repetitions and examples carried over from the GPT-5 era, tighten tool descriptions. (3) Re-evaluate blanket brevity instructions — GPT-5.6 is more concise by default than GPT-5.5; "Be concise" statements can make responses too short; replace with `text.verbosity` plus task-specific length requirements. (4) Move reasoning, tool calling, and multi-turn workloads to the Responses API. (5) Keep `reasoning.context` at `auto`/`all_turns`, using `current_turn` only when prior reasoning is irrelevant. (6) Explicitly add autonomy and approval boundaries rather than relying on spontaneous pausing. (7) `reasoning.mode: "pro"` is optional and independent of effort for quality-critical tasks. (8) Plan for refusal and stream pause handling.
