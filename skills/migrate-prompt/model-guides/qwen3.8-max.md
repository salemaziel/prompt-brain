# Qwen3.8-Max

## Reasoning / Thinking
- Typ: **hybrid, per Default an**. Die kommerzielle Qwen3.8-Serie (max, flash, 27b) ist auf der Deep-Thinking-Seite als „thinking mode enabled by default" geführt (das offene qwen3.8-2.4t-a95b dort als „thinking mode only") — ein Request ohne Thinking-Feld denkt. Abschalten pro Request über `enable_thinking: false`.
- Parameter-Platzierung ist SDK-abhängig: im OpenAI-Python-SDK gehören `enable_thinking`/`thinking_budget` in `extra_body` (kein Standard-OpenAI-Parameter), im Node.js-SDK werden sie als Top-Level-Properties übergeben, in DashScope direkt.
- `thinking_budget` deckelt die Reasoning-Tokens; Default ist laut API-Referenz die maximale Chain-of-Thought-Länge des Modells — für qwen3.8-max **262.144 Tokens** (die Konsole nennt abweichend Default 4.000, Bereich 1–32.768). Ist das Budget erschöpft, bricht das Modell das Denken ab und antwortet sofort.
- Reasoning kommt in `reasoning_content`, die Antwort in `content`. In der History wird `reasoning_content` ignoriert, **außer** `preserve_thinking: true` ist gesetzt (für qwen3.8-max dokumentiert) — dann fließt das frühere Reasoning in den Input und wird mitabgerechnet.
- Streaming ist wegen der Latenz empfohlen, aber nicht erzwungen: kommerzielle Thinking-Modelle unterstützen laut Doku auch synchrone Aufrufe (die Streaming-only-Einschränkung betrifft offene Modelle wie qwen3.5-122b-a10b und qwen3.5-27b).
- Thinking kostet Kontext: max. Input 983.616 Tokens im Thinking-Modus gegenüber 991.808 ohne; max. Output bleibt 131.072.
- Über den Anthropic-kompatiblen Messages-Endpoint: `thinking: {type: "enabled" | "disabled"}`; die Tiefe steuert `output_config.effort`, für qwen3.8-max Default `xhigh`, gültig `xhigh`/`medium`/`low`; `max` und `high` werden auf `xhigh` gemappt. `budget_tokens` ist als „to be deprecated" markiert (Doku: für neue Integrationen `effort`). Ob Thinking bei fehlendem `thinking`-Feld auf diesem Endpoint läuft, sagt die Seite nicht (unbelegt).

## Prompting-Stil
- **Es gibt keine modell-spezifische Prompting-Seite für qwen3.8-max.** Offiziell ist nur Alibabas generischer Prompt-Engineering-Guide: Rahmen aus Context, Objective, Style, Tone, Audience, Response; Few-Shot-Beispiele für konsistente Form; explizite Schrittlisten bei komplexen Aufgaben; seltene Trennzeichen (`###`, `===`, `>>>`) zur Abgrenzung von Abschnitten. Alles darüber hinaus ist für dieses Modell unbelegt.
- Weil Thinking per Default läuft, gehört Tiefensteuerung in `thinking_budget` statt in den Prompttext — „denke Schritt für Schritt"-Scaffolding dupliziert nur das eingebaute Reasoning und verlängert die sichtbare Antwort.
- JSON: im `json_object`-Modus muss das Wort **„JSON" wörtlich im Prompt** stehen (case-insensitive), im `json_schema`-Modus nicht. Die Doku empfiehlt trotzdem, Feldnamen, Typen und ein Beispiel im Prompt zu beschreiben.
- Prompt-Reihenfolge cache-freundlich bauen: wiederkehrende Inhalte an den Anfang, variable ans Ende; bei Vision-Aufgaben stabile Bilder/Videos **vor** die wechselnde Textfrage.
- Für lange agentische Läufe die vollständige Aufgabenspezifikation vorab geben — Alibaba positioniert den 0902-Snapshot ausdrücklich für „long-horizon autonomous development" und „multi-tool orchestration and end-to-end task delivery".

## Stärken & Schwächen (prompt-relevant)
- Architektur laut Pressemitteilung: 2,4 Billionen Parameter als **Sparse MoE mit hybridem Attention-Mechanismus**, davon nur 95 Mrd. aktiv; 1M Kontext; nativ multimodal („hundred-page documents, full television series, or 100-hour livestreams").
- Stärken: agentisches Coding und Langhorizont-Arbeit (interner Testlauf: ein reales Software-Projekt über 16 Tage autonom); Vision/Chart-Reasoning und Dokumentenparsing (im 0902-Snapshot nochmals nachgeschärft); Function Calling, Structured Outputs, Web Search (rollende id nur in Peking und Singapur, Snapshot 0902 in allen gelisteten Regionen), Prefix Completion und Context Caching sind für das Modell freigeschaltet; erreichbar über OpenAI-, Anthropic- und DashScope-kompatible Endpoints.
- Schwächen/Eigenheiten: **kein Fine-Tuning**; Batch-Inferenz je nach Region nicht verfügbar (u. a. Singapur, Deutschland, USA, Japan); Prefix-Continuation ist nur für den **Non-Thinking-Modus** dokumentiert — Prefill und Thinking kombinieren sich also nicht; die Doku warnt selbst, dass die nutzbare Länge „may vary depending on different combinations of API input parameters".
- Nicht publiziert und damit unbelegt: Knowledge Cutoff, empfohlene Sampling-Parameter (`temperature`/`top_p`/`top_k`), Verhalten bei out-of-range `thinking_budget`.

## Output- & Format-Konventionen
- Kontextfenster 1.000.000 Tokens; max. Input 991.808 (ohne Thinking) bzw. 983.616 (mit); max. Output 131.072; max. Chain-of-Thought 262.144. Input Text/Bild/Video, Output nur Text.
- Structured Output: `response_format` mit `json_object` (Keyword-Pflicht) oder `json_schema` mit `strict: true`; die Schema-Variante ist ausdrücklich für die Qwen3.8-Max-Serie dokumentiert. Einschränkungen laut Structured-Output-Seite: `json_schema` ist für Modelle der Region Singapur „not supported yet" (die Modellseite markiert Structured Outputs in Singapur dagegen als unterstützt — widersprüchlich, vor Produktion testen), und multimodale Eingaben (Bild, Video, Audio) fallen automatisch auf `json_object` zurück — dann gilt die „JSON"-Keyword-Pflicht, und es gibt keine Schema-Garantie. Auf dem Anthropic-kompatiblen Endpoint läuft dasselbe über `output_config` mit `format.type: "json_schema"`, mit strikter Durchsetzung für die 3.8/3.7-Linie.
- Prefix Completion: letzte Message mit `role: "assistant"` und `partial: true`; das Präfix wird als Input abgerechnet und muss vom Aufrufer selbst mit der Fortsetzung konkateniert werden.
- Context Cache: implizit per Default aktiv und **nicht abschaltbar**, Mindestlänge **1.024 Tokens**; explizit über `cache_control: {"type": "ephemeral"}`; Gültigkeit 5 Minuten, die sich bei jedem Treffer zurücksetzt. Dokumentierte Miss-Ursachen: abgelaufener Cache-Block, mehr als 20 Content-Blöcke zwischen `cache_control`-Marker und passendem Inhalt, nicht identische Tool-Definitionen (inkl. Tool- und Feldreihenfolge) sowie — implizit — ein abweichendes Prefix. Die Doku sagt ausdrücklich, dass die Trefferquote auch bei identischem Kontext nicht 100 % ist.
- Preis ohne Längenstaffel über das ganze 1M-Fenster; Referenz Singapur $2 Input / $6 Output pro 1M Tokens, Cache-Treffer deutlich günstiger (impliziter Cache-Input $0,25, expliziter Cache-Read $0,17). Andere Regionen weichen ab — siehe Modellseite.
- Ids: `qwen3.8-max` ist der rollende Alias, `qwen3.8-max-0902` (Alias `qwen3.8-max-2026-09-02`, veröffentlicht 2026-09-02) der gepinnte Snapshot. Der Doku-URL-Slug lautet `qwen3-8-max` — das ist **nicht** die API-id.
- Der Anthropic-kompatible Endpoint bietet nur `/v1/messages`, kein `/v1/models`: die Modell-id muss in Clients manuell konfiguriert werden.

## Migrations-Hinweise
- **VON qwen3.8-max weg**: Qwen-spezifische Felder nicht 1:1 übernehmen — `enable_thinking`, `thinking_budget`, `preserve_thinking`, `reasoning_content`, `partial: true`-Prefill und `cache_control`-Marker sind hier Model-Studio-spezifisch ausgeprägt; gleichnamige oder ähnliche Felder anderer Anbieter haben andere Namen, Bereiche und Defaults — Denksteuerung, Prefill und Caching anhand des Ziel-Guides neu abbilden oder entfernen. Denkt das Zielmodell nicht von selbst, explizite Reasoning-/Selbstprüfungs-Schritte wieder in den Prompt schreiben. Das 1M-Fenster schrumpft auf den meisten Zielen — Chunking neu auslegen. Video-Input entfällt bei den meisten Zielen. Die „JSON"-Keyword-Pflicht des `json_object`-Modus ist eine Qwen-Eigenheit und kann gestrichen werden; Schema-Dialekt und `strict`-Semantik des Ziels prüfen. Cache-Regeln (1.024-Token-Minimum, stabiles Präfix zuerst) sind Qwen-Zahlen und gelten anderswo nicht.
- **ZU qwen3.8-max migrieren**: Wichtigster Bruch — **Thinking läuft, sofern nicht `enable_thinking: false` gesetzt wird.** Ein von einem Non-Thinking-Modell portierter Prompt denkt plötzlich: Latenz, Kosten und `max_tokens` neu bemessen und `thinking_budget` setzen, sonst steht bis zu 262.144 Tokens Chain-of-Thought im Budget. Explizite CoT-Aufforderungen aus dem Prompt streichen und die Tiefe über `thinking_budget` regeln. Bei Multi-Turn entscheidet `preserve_thinking`, ob früheres Reasoning überhaupt ankommt — Default ist ignorieren. Nutzt eine Route Assistant-Prefill, `enable_thinking: false` setzen oder auf Structured Output umstellen (strikt nur ohne Bild-/Video-Input und — laut Structured-Output-Seite — außerhalb Singapurs, sonst nur `json_object` mit „JSON" im Prompt; Partial Mode ist nur für Non-Thinking dokumentiert). Aus der Anthropic-Welt kommend: `thinking.type` funktioniert, `budget_tokens` durch `output_config.effort` ersetzen; ein `effort: high`/`max` aus Claude-Prompts landet hier auf `xhigh` (Default, höchste Stufe), für mittlere Tiefe explizit `medium` setzen (der Hebel `thinking_budget` gehört auf die OpenAI-/DashScope-Route); die Modell-id muss manuell konfiguriert werden (kein `/v1/models`). Stabiles Prompt-Präfix nach vorn stellen, damit der implizite Prefix-Cache greift; für den expliziten Cache müssen Tool-Definitionen inklusive Reihenfolge über alle Requests identisch bleiben. Für Reproduzierbarkeit `qwen3.8-max-0902` pinnen statt der rollenden id (Achtung: der Snapshot ist in Frankfurt/USA/Tokio/Hongkong auf 150.000 TPM gedeckelt, die rollende id hat dort 5.000.000). Fine-Tuning-Routen haben hier keinen Pfad, Batch-Inferenz je nach Region ebenfalls nicht.
- Nicht verwechseln: Die versionslose Vendor-id `qwen-max` ist ein eigenes, weiterhin angebotenes Altmodell (funktional = `qwen-max-2025-01-25`, 32.768 Kontext, max. Output 8.192, kein dokumentierter Thinking-Modus) und **nicht** qwen3.8-max — ein Prompt für `model="qwen-max"` wird von diesem Guide nicht beschrieben. Dasselbe gilt für `qwen-plus`/`qwen-flash` (eigene Hybridmodelle, laut Deep-Thinking-Seite Thinking per Default aus; siehe die Guides qwen3.7-plus und qwen3.8-flash für die aktuellen Stufen).
