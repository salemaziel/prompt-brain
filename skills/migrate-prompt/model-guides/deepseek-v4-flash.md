# DeepSeek-V4-Flash

## Reasoning / Thinking
- **A single hybrid model instead of two IDs**: `deepseek-v4-flash` handles both non-thinking and thinking; a separate reasoner ID no longer exists. Thinking is **on by default** (default effort `high`) — to obtain V3-style direct responses, it must be explicitly disabled: OpenAI format `{"thinking": {"type": "enabled" | "disabled"}}` (in the OpenAI SDK within `extra_body`); Anthropic format: identical toggle `thinking: {"type": "enabled"|"disabled"}` (`budget_tokens` is ignored), effort via `output_config: {"effort": "low|high|max"}`; Responses API: `reasoning: {"effort": "none|low|high|max"}` (`none` = off). `reasoning_effort` also accepts `none` (thinking off); mapping: minimal → low, medium/xhigh → high, ultra → max.
- Effort values: `low | high (default) | max`. Thinking mode ignores `temperature`, `presence_penalty`, and `frequency_penalty` (no error, no effect). `top_p` takes effect only in thinking mode (effectively 0.95–1.0, lower values → 0.95); in non-thinking mode, `top_p` is fixed at 1.0.
- Chain-of-Thought is returned in `reasoning_content` at the same level as `content`. **Without** tool calls, it does not need to be passed back in subsequent turns; **with** tool calls, intermediate `reasoning_content` must be concatenated into context and returned to the API.
- Token level (Model Card): Reasoning is framed as `<think>{reasoning}</think>`, non-thinking is encoded via an immediate `</think>` following the assistant marker; with `reasoning_effort="max"`, the template prepends a prefix to the system prompt ("Reasoning Effort: Absolute maximum with no shortcuts permitted…"). Three named modes: Non-think, Think High, Think Max (Think Max recommends ≥ 384K context window).

## Prompting Style
- System prompt is first-class: Template is `<｜begin▁of▁sentence｜>{system_prompt}<｜User｜>{user_message}<｜Assistant｜>` — placed at the very beginning of the sequence.
- **JSON requires three simultaneous elements**: the word "json" in the system or user prompt, an example of the desired JSON format in the prompt, and a sufficiently high `max_tokens` so that the string is not cut off midway. Alternative output steering via **Chat Prefix Completion**: final message `role: "assistant"` with `prefix: True` against `base_url="https://api.deepseek.com/beta"`, combined with `stop` (e.g. `["```"]`) to suppress trailing prose.
- **Prompt order impacts cost**: Context Caching is active for everyone without code modifications, but triggers only on **exact full-prefix matches** of a persisted cache unit and operates on a best-effort basis — consequently: place static material (system instructions, reference documents) at the beginning, variable content at the end (not explicitly documented as a recommendation, only demonstrated this way in examples — (unbelegt)); inspect via `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`.
- Tool schemas are passed via the `tools` field; internally, invocations are rendered as DSML (`<｜DSML｜invoke name="…">`, parameters with `string="true"` for raw strings, `string="false"` for JSON values) — relevant only when hand-crafting tool-call examples. Local deployments: Model Card recommends `temperature = 1.0`, `top_p = 1.0`.

## Strengths & Weaknesses (prompt-relevant)
- Efficiency tier: MoE with 284B total / 13B activated, mixed FP4+FP8, hybrid attention (Compressed Sparse Attention + Heavily Compressed Attention) plus Manifold-Constrained Hyper-Connections (mHC). As of 2026-08-14: price $0.14 / $0.28 per 1M input (cache miss) / output tokens with a concurrency limit of 2500 — ~3× cheaper input and 5× concurrency compared to V4-Pro. (The Model Card statement "27% FLOPs / 10% KV cache vs. V3.2" applies explicitly to **V4-Pro**, not Flash.)
- Strengths (benchmark values, non-think column unless specified): Coding (HumanEval 69.5; Think High 88.4, Think Max 91.6), math (GSM8K 90.8), long context (LongBench-V2 44.7); Max mode primarily boosts knowledge-intensive tasks (SimpleQA-Verified 23.1 → 34.1).
- Weaknesses: Factual knowledge deficit: SimpleQA-Verified 23.1 (Non-Think) / 28.9 (High) / 34.1 (Max) versus V4-Pro at 45.0 / 46.2 / 57.9 — knowledge-heavy prompts require dedicated grounding or belong on Pro.
- Additional limitations: FIM completion is non-thinking only; JSON output occasionally returns empty `content` (adjust prompt); Think Max expects ≥ 384K context. The Anthropic-compatible endpoint does not support document blocks (image blocks are supported, but serviced by V4.1-Flash onto which the ID is routed), no `anthropic-beta`/`anthropic-version` headers, no `top_k`, no `cache_control`, no MCP tool use, and ignores `budget_tokens`.

## Output & Format Conventions
- **1M context window, up to 384K output tokens.** Supported: JSON Output, Tool Calls, Responses API, Anthropic API, Chat Prefix Completion (Beta); FIM completion in non-thinking mode only. Final version: `DeepSeek-V4-Flash-0731`. Since 2026-09-10, V4-Flash has been shut down; `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp` are temporarily routed to DeepSeek-V4.1-Flash and billed at Flash rates. DeepSeek-V4-Flash-Vision-Exp (2026-08-21 to 2026-09-10, experimental) matched V4-Flash on text performance and additionally accepted images (up to 384 tokens per image).
- Base URLs: `https://api.deepseek.com` (OpenAI SDK), `https://api.deepseek.com/anthropic` (Anthropic SDK), `https://api.deepseek.com/beta` (Prefill/FIM). On the Anthropic endpoint, `claude-haiku*`/`claude-sonnet*` map to `deepseek-flash` (V4.1-Flash); unknown model names also fall back to it.
- `response_format` supports only `text` (default) and `json_object` — **no `json_schema`**; strict schema adherence must be enforced via prompt + downstream validation. Sampling: `temperature` 0–2 (default 1), `top_p` up to 1 (default 1), max 16 `stop` sequences, `logprobs` with `top_logprobs` 0–20, `tool_choice` none/auto/required/specific — `required` and named tools return HTTP 400 in thinking mode (only usable with `thinking: disabled`); `max_tokens` defaults: 8K (Non-Thinking) / 64K (Thinking) / 128K (`max`), maximum 384K; `frequency_penalty` and `presence_penalty` are no longer supported and remain ineffective.

## Migration Notes
- **Migrating TO V4-Flash is no longer possible** — use target `deepseek-v4.1-flash` (alias `deepseek-flash`).
- **MIGRATING FROM deepseek-v4-flash**: Remove `thinking`/`reasoning_effort` parameters and all `reasoning_content` processing; if target has no native reasoning mode, re-add explicit Chain-of-Thought instructions to the prompt; if target enforces `json_schema`, convert prompt-embedded JSON examples into genuine schemas and remove mandatory literal "json"; reintroduce `presence_penalty`/`frequency_penalty` only if supported by target; replace `prefix: True` prefill with target's prefill equivalent or stop-sequence workarounds. Flash → Pro migration within the family requires **no** prompt rewrite (identical parameters, identical context/output limits) — only knowledge-heavy prompts justify ~3× more expensive input.
- **MIGRATING TO deepseek-v4-flash** (historical, from `deepseek-v3` / `deepseek-chat` / `deepseek-r1` / `deepseek-reasoner`): Legacy IDs are **gone** — `deepseek-chat` and `deepseek-reasoner` became completely unreachable after 2026-07-24 15:59 UTC; official directive: "Keep base_url, just update model to deepseek-v4-pro or deepseek-v4-flash." Specifically: (1) The chat-vs-reasoner model split becomes a **mode flag** — a former `deepseek-chat` prompt now requires `thinking: {"type": "disabled"}` or `reasoning.effort: "none"`, while a former reasoner prompt requires nothing. (2) Remove `frequency_penalty`/`presence_penalty` from requests. (3) Remove `temperature`/`top_p` tuning from reasoning prompts — R1 advice like "set temperature 0.6" has no effect. (4) If orchestrating tool calls, `reasoning_content` must now be passed back into subsequent turns rather than stripped. (5) 1M context is default, 384K output is supported — remove chunking / partial-summary scaffolding from the V3/R1 era. (6) Reorder prompts: static instructions/references upfront because prefix caching rewards exact prefix matches (derived from examples — (unbelegt)). (7) Replace "Think step by step" scaffolding with `reasoning_effort` low/high/max — thinking depth is now a parameter, not prompt text.
