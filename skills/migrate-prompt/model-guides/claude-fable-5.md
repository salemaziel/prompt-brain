# Claude Fable 5

## Reasoning / Thinking
- Type: **adaptive, always on**. Omit `thinking` or send `{type: "adaptive"}`; `{type: "disabled"}` and `{type: "enabled", budget_tokens: N}` both return 400. Depth is controlled exclusively via `output_config.effort` (`low | medium | high | xhigh | max`), default `high`.
- `effort` on Fable 5 is **request-level**: switching it between requests invalidates the cached prefixes of earlier turns. Per-message effort (beta `mid-conversation-output-config-2026-07-01`) is not supported — with that beta header, an effort system message returns 400. Keep effort constant in cached conversations.
- `thinking.display` default `"omitted"` (empty thinking blocks), `"summarized"` returns a summary; the raw chain of thought is never returned. Text that the model writes between tool calls arrives as a progress `thinking` block, not as a `text` block; interleaved thinking runs automatically.
- Return thinking blocks unmodified. Fable 5 blocks are read only by Fable 5, Mythos 5, Fable 5.1, and Mythos 5.1; for any other model, the API discards them before the model and does not bill them.
- Non-default values for `temperature`/`top_p`/`top_k` → 400.

## Prompting Style
- **Longer turns**: individual requests on hard tasks run for many minutes at higher effort, autonomous runs for hours — adjust client timeouts, streaming, and progress indicators before migration; monitor long runs asynchronously (e.g. via scheduled job) rather than waiting synchronously.
- **Effort**: `high` as default for most tasks, `xhigh` for the most capacity-critical workloads, `medium`/`low` for routine work — lower levels often perform better than `xhigh` on predecessor models according to docs. At `high`/`xhigh`, set `max_tokens` generously (thinking + answer share a single limit).
- **Concise instructions instead of lists**: instruction following is so strong that a succinct sentence replaces an entire list of behaviors. The documentation provides ready-to-use system prompt snippets for: anti-overplanning ("when you have enough information to act, act"), no unprompted refactoring/tidying, result first instead of rambling, asking clarifying questions only for destructive actions/scope changes/missing input, verifying progress statements against tool results, boundaries (for problem descriptions, assess only, do not fix), asynchronous parallel sub-agents, memory file, readability addendum for the final summary.
- Optionally, provide a `send_to_user` tool for verbatim intermediate output from long-running agents — rarely used without explicit calling instructions in the system prompt; do not route narration or reasoning through it.
- **Streamline** migrated prompts/skills: skills written for earlier models are often overly prescriptive and can degrade quality — test older instructions against default performance and prune if necessary. Include the reason behind the request; explicitly require self-verification (separate verifier sub-agents with fresh context at fixed intervals rather than self-critique).
- **Do not request reasoning in the response text**: prompts, skills, and tool descriptions that prompt the model to write out its thinking/reasoning — verbatim or in a fixed format (`<thinking>`, `<reasoning>`, or scratchpad section before the answer, `reasoning`/`thinking`/`trace` field in JSON output or tool input, reasoning log, reasoning "verbatim"/"in full") — can be rejected with `stop_reason: "refusal"` and `stop_details.category: "reasoning_extraction"`. Instead, request a brief explanation, evidence, or a summary of executed steps; if reasoning itself is needed, keep thinking enabled and read thinking blocks with `display: "summarized"`. This category has no fallback model (modify the prompt rather than resending), and refusals occurring before any output are billed.

## Strengths & Weaknesses (prompt-relevant)
- Strengths (at release, June 2026, compared to Opus 4.8): long-horizon autonomy over multi-day, goal-directed runs; first-shot correctness on complex, well-specified problems; vision on dense technical images and screenshots (with bash/crop tools even on rotated, blurry, or noisy images); enterprise workflows (financial analysis, spreadsheets, slides, documents); code review and debugging; handling ambiguous, multi-threaded requests; reliable delegation to parallel sub-agents. The successor Fable 5.1 improves primarily in long agentic coding, research, and document work according to the vendor.
- Weaknesses / quirks: excessive context gathering and deliberation at high effort on routine tasks; occasional unprompted actions (drafting emails, backup branches); hard-to-read shorthand in long agentic conversations (arrow chains, references to unseen thinking); deep into long sessions, rare premature stops with a declaration of intent without a tool call or unnecessary questions (counteract with autonomy reminders); rare context-budget anxiety (suggesting new session/hand-off), usually triggered by a visible token countdown in the harness — avoid countdowns or use reassuring reminders.
- Safety classifiers for offensive cybersecurity, biology/life sciences, and reasoning extraction; even benign work in these domains can trigger `stop_reason: "refusal"`. The model is not intended for offensive security and bio work.

## Output & Format Conventions
- 1M context window, 128K output tokens (synchronous Messages API); stream large outputs. Minimum cacheable prefix: 512 tokens. Opus 4.7-generation tokenizer: roughly 30% more tokens for the same text compared to older models.
- No assistant prefill (400) — use Structured Outputs (`output_config.format`) or system prompt instructions. `tool_choice` accepts `auto`, `none`, `any`, and `tool` (forced tool use is still possible here). Mid-conversation system messages and tool changes are supported.
- Refusals arrive as HTTP 200 with `stop_reason: "refusal"` and `stop_details` (`category`, `explanation`) — check before reading `content`, discard partial output. Since September 24, 2026, refusals occurring before any output are billed in categories `bio`, `frontier_llm`, and `reasoning_extraction`, but not in other categories; mid-stream refusals bill input plus already streamed output.
- **Fallbacks are opt-in** (beta, Claude API only; on Bedrock, Google Cloud, and Foundry use SDK middleware instead): `fallbacks: "default"` with header `server-side-fallback-2026-07-01`, or an explicit list such as `fallbacks: [{"model": "claude-opus-4-8"}]` (the list format also accepts `server-side-fallback-2026-06-01`). Documentation mentions Opus 4.8 as a fallback target; eligible targets are returned by the Models API as `allowed_fallback_models`.
- Pricing per MTok: input $10, output $50, 5m cache write $12.50, 1h cache write $20, cache read $1 (0.1× input); batch 50% discount.
- Model IDs: Claude API, Google Cloud, Microsoft Foundry, and Claude Platform on AWS `claude-fable-5`; Amazon Bedrock `anthropic.claude-fable-5`. Reliable knowledge cutoff Jan 2026.
- **30-day retention mandatory** (Covered Model): no ZDR without explicit authorization from Anthropic; on the Claude API, an organization without an appropriate retention configuration returns 400 `invalid_request_error`.

## Migration Notes
- **Status**: Fable 5 is considered legacy by the vendor and Anthropic recommends migrating to Claude Fable 5.1 (`claude-fable-5-1`); consider this target for new migrations. The model remains available (lifecycle status *Active (legacy)*, retirement not before June 9, 2027).
- **MIGRATING FROM claude-fable-5**: Fable 5 thinking blocks are read only by Fable 5.1 (or Mythos 5/5.1); on any other target they are discarded (not billed) and the model replans without the prior reasoning. Do not carry over effort settings; rerun effort sweeps on the target. Adjust refusal/fallback configuration to target (`fallbacks` targets are model-specific). Prefill, sampling, forced tool use, and ZDR follow the target guide.
- **MIGRATING TO claude-fable-5**: Remove any `thinking` configuration other than `adaptive` (including `disabled` and `budget_tokens`); remove non-default sampling and prefills; remove per-message effort system messages (400) and keep effort constant per cached conversation; ensure 30-day retention; add `refusal` handling and configure fallbacks explicitly; rerun effort sweep including `medium`/`low` for routine work; adjust timeouts/streaming for long turns; remove over-prescriptive scaffolding and add concise behavioral snippets instead; review system prompts and skills for reflection/show-your-thinking instructions and replace them (`reasoning_extraction`, not retried by `fallbacks: "default"`).
