# Gemini 3.8 Flash

## Reasoning / Thinking
- Type: **always on**, depth controlled exclusively via the string enum `thinking_level` with `low | medium | high`, default **`medium`**. `minimal` is rejected for this model and returns an error — unlike `gemini-3.6-flash`, `gemini-3.5-flash` (deprecated, routed to 3.6 Flash), and `gemini-3.5-flash-lite`, which support `minimal`.
- `thinking_budget` is deprecated; control via token budget no longer exists. Google explicitly describes the levels as "relative allowances for thinking rather than strict token guarantees" — thus not a hard token guarantee.
- Level selection according to documentation, mapped to task types: low level for fact retrieval and classification ("Use minimal or low thinking for fact retrieval or classification"), default level for concept comparison and creative reasoning ("Use default thinking for comparing concepts or creative reasoning"), maximum level for advanced coding, math, and multi-step planning ("Use maximum thinking for advanced coding, math, or multi-step planning").
- Billing: "response pricing is the sum of output tokens and thinking tokens"; thought tokens are reported in `total_thought_tokens`. The full thought is billed, even when only the summary is delivered ("Pricing is based on the full thought tokens the model needs to generate, despite only the summary being output").
- A Thought Signature is "An encrypted representation of the model's internal reasoning state." and carries reasoning continuity across multiple turns. In stateful operation, the server manages it ("The server automatically manages the conversation state, including all thought blocks and signatures"); in stateless operation, **all** `thought` blocks must be returned unchanged. According to documentation, preserving reasoning context across turns improves performance on complex multi-step tasks.
- Summaries controlled via `thinking_summaries: "auto"`, disabled with `"none"`.

## Prompting Style
- **Prompt concisely and directly.** "Be concise. Gemini 3.x responds best to direct, clear instructions." Verbose prompt engineering techniques designed for older models cause the model to "over-analyze" according to documentation — strip lingering step-by-step chains, persona prose, and repeatedly reiterated instructions.
- **Request verbosity explicitly.** Default is low verbosity and direct; an explanatory or friendly tone must be requested explicitly in the prompt.
- **Long-context layout:** Place data first, specific instruction or question at the **end**, and start the question with an anchor like "Based on the preceding information...".
- **No more sampling controls:** `temperature`, `top_p`, and `top_k` no longer belong in the generation config. (For Gemini 3 generally, Google recommends keeping `temperature` at default 1.0 — lowering it can produce looping or degraded performance on math/reasoning.)
- **No Assistant prefill:** Remove prefilled model turns ("remove prefilled model turns"). Enforce format via Structured Outputs or system instructions.
- Agentic: The launch post describes "greater diligence" on complex tasks, implemented through "executing extra reasoning steps, and calling tools iteratively". Explicitly set scope, termination criteria, and tool budgets instead of relying on self-limitation.

## Strengths & Weaknesses (prompt-relevant)
- Strengths: "long-horizon software engineering, autonomous agents, and complex enterprise workflows" (formulation from model listing). The launch post calls it "our best reasoning and coding model yet, at the same speed and low cost of 3.7 Flash" and substantiates this via DeepSWE v1.1 ("outperforms most larger frontier models in autonomously solving complex engineering problems end to end, only at a fraction of the cost"), Vals Finance Agent V2, Harvey's Legal Agent Benchmark, and 54.9% on HLE-Verified. The Model Card lists "software engineering, agent tasks, and complex knowledge workflows" as deployment domains.
- Tier positioning: "Our most intelligent **Flash** model" — a superlative within the Flash series, not across the entire lineup. DeepMind positions it as "designed for cost-effective scaling of general-purpose, production-ready agents". The Pro tier (`gemini-3.1-pro-preview`, "Advanced intelligence, complex problem-solving skills") continues to exist alongside it; for maximum reasoning depth, 3.8 Flash is not automatically the pinnacle.
- It is the default model for Managed Agents (Antigravity).
- Weaknesses: Typical foundation model hallucinations according to Model Card; jailbreak susceptibility (mitigations recently reinforced); occasional slowness or timeouts; **higher token consumption at higher effort levels**; according to Google "can use more tokens on longer running and complex tasks, by design" — lower `thinking_level` for everyday tasks; slight regression in multilingual safety compared to 3.7 Flash — do not thin out guardrails in multilingual prompts.
- Knowledge cutoff **March 2026**, in some domains only up to January 2025 — provide time-sensitive facts in the prompt rather than querying them.
- Known error class in tool calling: `Malformed_Function_Call` associated with text preceding the tool call.

## Output & Format Conventions
- 1,048,576 input tokens / 65,536 output tokens. Input: text, image, video, audio, PDF → output text only.
- Supported: Structured Outputs, Function Calling, Caching, Code Execution, Search Grounding, URL Context, File Search, Grounding with Google Maps, Batch API, Computer Use (Preview), Flex and Priority inference. **Not** supported: audio generation, image generation, Live API. Image segmentation (pixel masks) is not supported in Gemini 3.x according to Google.
- Function Calling: Multimodal assets belong in the response payload, inline instructions are formatted with `\n\n`; on the `generateContent` API, each `FunctionResponse` must carry `call_id` and `name`, with exactly one response per call and an exact matching name.
- Multi-Turn: Server-side `previous_interaction_id` is the prescribed standard path; without it, full, unaltered history including thought signatures must be sent in `contents`.
- Pricing per 1M tokens (introductory pricing through 2026-12-31): input $0.75, output $3.75; after 2027-01-01 $1.50 / $7.50. Context caching $0.075 → $0.15 and storage $0.50 → $1.00 per 1M tokens/hour. Batch API 50% discount. Same pricing tier as `gemini-3.6-flash`.
- SDK: Multimodal function responses require an SDK "newer than 2.0.0" according to code examples (https://ai.google.dev/gemini-api/docs/gemini-3).

## Migration Notes
- **MIGRATING FROM gemini-3.8-flash**: Translate `thinking_level` to the target model's control scheme (`thinking_budget`, `reasoning_effort`, or similar) and re-estimate token budgets if needed; set `temperature`/`top_p`/`top_k` explicitly again if target expects sampling; remove `previous_interaction_id` and thought signature logic and manage history manually; re-enrich concise prompts if the target needs explicit step-by-step scaffolding; re-evaluate tone/verbosity instructions (they only compensate for the terse 3.8 default); align modality support — audio, video, and PDF input are not universally available; verify 1M input / 64k output against target limits.
- **MIGRATING TO gemini-3.8-flash**: **Remove** `temperature`, `top_p`, `top_k`, and `candidate_count` from the generation config; replace `thinking_budget` with `thinking_level` — `minimal` does not exist here and throws an error, so upgrade `minimal` paths coming from 3.6 Flash / 3.5 Flash(-Lite) to `low` and re-measure latency/quality; remove prefilled model turns; switch multi-turn to `previous_interaction_id` or pass through thought signatures unchanged; add `call_id` and `name` to each `FunctionResponse`; remove verbose prompt engineering remnants; in long contexts, place data first and question at the end; add explicit tone and length instructions if previous outputs were more conversational; do not migrate segmentation workloads here.
- Specifically **from `gemini-3.7-flash`**: Identical (most recently published) list price, identical token limits, identical `low | medium | high` ladder with `medium` default — migration is essentially the model ID swap plus the function calling and turn validation points above. Since 2026-10-08, `gemini-3.7-flash` has been deprecated; "API requests to `gemini-3.7-flash` are automatically routed to `gemini-3.8-flash`" — a prompt tuned for 3.7 already runs on 3.8, requiring only the model string to be updated. As a more token-efficient alternative, Google notes "Alternatively, Gemini 3.6 Flash remains supported".
