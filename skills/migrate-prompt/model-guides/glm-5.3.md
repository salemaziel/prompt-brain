# GLM-5.3

## Reasoning / Thinking
- Typ: **erzwungen an**. `thinking: {"type": "enabled"}` ist der einzige zulässige Wert — „Disabling reasoning is no longer supported". Ein Request mit `thinking.type: "disabled"` schlägt fehl; auf GLM-5.2/5.1/5/4.6 entscheidet das Modell selbst, ob es denkt.
- Tiefe ausschließlich über `reasoning_effort`: `low` (mild inference, nur auf 5.3/5.3-Flash) | `high` (enhanced inference) | `max` (deep inference, laut Doku **„default and recommended"**). Auf dem Standard-API-Endpoint erzeugt jeder andere Wert der plattformweiten Enum einen Fehler („Any other input will result in an error"); auf dem Coding-Plan-Endpoint werden `none`/`minimal`/`low` auf `low`, `medium`/`high` auf `high` und `xhigh`/`max` auf `max` gemappt; in den offenen Gewichten fällt ein fehlender oder unbekannter Wert still auf `max` zurück („defaults to max if not passed (or if set to any other value)"). Auf GLM-5.2 wurden `none`/`minimal` (Thinking aus), `low`/`medium` (→ `high`) und `xhigh` (→ `max`) noch gemappt.
- Es gibt damit **keinen Zero-Thinking-Pfad**: „Thinking process will consume extra tokens, please manage your tokens." Bei bisher thinking-freien Workloads das Token-Budget neu bemessen; `low` ist die Untergrenze, nicht „aus". Ob Reasoning-Tokens gegen dasselbe `max_tokens` wie die Antwort laufen, sagt keine Z.ai-Quelle (unbelegt).
- Reasoning-Ausgabe: non-streaming als Feld `reasoning_content` neben `content`; im Stream erst `delta.reasoning_content`, danach `delta.content`.
- `clear_thinking` verwirft das Reasoning vorheriger Turns. Preserved Thinking (`clear_thinking: false`) ist auf dem Standard-API-Endpoint per Default aus, auf dem Coding-Plan-Endpoint per Default an; im Chat-Template der offenen Gewichte steht `clear_thinking` auf `false` — für Chat-Szenarien empfiehlt die Modellkarte ausdrücklich, `clear_thinking=true` zu übergeben. Für kohärente Mehr-Turn-Läufe auf `false` setzen und das historische `reasoning_content` unverändert zurückschicken — „All consecutive reasoning_content blocks must exactly match the original sequence", sonst geht der Cache-Vorteil verloren.

## Prompting-Stil
- Z.ai positioniert 5.3 als Coding- und Agent-Modell („comprehensive advancements in complex software engineering and agent capabilities") — direktiv und aufgabenorientiert prompten, keine Rollen-Prosa (unbelegt).
- Offizielles Task-Schema für Agent-Prompts, vier Blöcke: **Goal** (was gebaut/geändert wird), **Context** (betroffene Dateien, Fehlermeldungen, Beispiele), **Constraints** (Coding-Standards, Architektur-, Security-, Dependency-Regeln), **Done when** (Abnahmekriterium: Tests grün, Bug nicht mehr reproduzierbar).
- Drei Kontext-Ebenen sauber trennen: Task Context (der Prompt), Project Context (Repo-Struktur + Engineering-Regeln), Environment Context (Tools, Rechte, Ausführungsumgebung). Regel der Doku: „Put temporary instructions in the prompt, and put long-lived rules in project-level configuration files."
- Bei komplexen Aufgaben eine **Planungsphase** vorschalten (Codebase erkunden, Scope festlegen, Vorgehen bestätigen), statt sofort Code anzufordern — direkte Code-Aufforderungen führen laut Doku zu Logikfehlern und Nacharbeit.
- Sessions schmal halten: eine Session pro Aufgabe, lange Sessions per Zusammenfassung schneiden, Verzweigungen in einer neuen Session.
- `temperature` und `top_p` **nicht gleichzeitig** verstellen — die Migrationsseite empfiehlt ausdrücklich, nur einen der beiden Werte zu tunen.
- Eine GLM-5.3-spezifische Prompt-Engineering-Seite existiert nicht; jede darüber hinausgehende Stilaussage ist unbelegt.

## Stärken & Schwächen (prompt-relevant)
- Stärken: agentisches Coding in realistischen Szenarien (+50 % gegenüber GLM-5.2 auf Z.ai Code Bench, Terminal-Bench 3.0 von 4.6 auf 28.3); emergente Security-/Vulnerability-Fähigkeiten (CyberGym 84,5 %, ExploitBench 54,4 %); höhere Token-Effizienz laut Z.ai (bei Max-Effort 34,5 % bei rund 75K Output-Tokens pro Task gegenüber 23,4 % bei 96K für GLM-5.2); 1M Kontext und 128K Output in einem Modell; Context Caching mit ausgewiesenen `cached_tokens`.
- Basis ist laut offizieller Modellkarte **dasselbe Basismodell wie GLM-5.2** („same base model as GLM-5.2"), der Zugewinn kommt aus dem Post-Training — inhaltlich trägt ein 5.2-Prompt weiter, es bricht nur der Thinking-Vertrag.
- Schwächen/Eigenheiten: **text-only** („GLM-5.3 currently supports text-only inputs"), also keine Bild-Eingabe — visuelle Fähigkeiten führen die Release Notes nur für `glm-5.3-flash`; enge `reasoning_effort`-Enum ohne `medium`/`xhigh`, portierte Effort-Werte anderer Anbieter laufen auf der Standard-API in einen Fehler, beim Self-Hosting dagegen still auf `max` (kein Fehler, höchste Kosten); kein publizierter Knowledge Cutoff (unbelegt); als Drittanbieter hostet Mistral das Modell unverändert als `zai-glm-5-3` (GA, laut Mistral global und EU, noch nicht über den US-Endpoint); weitere Dritt-Clouds sind nicht belegt (unbelegt).
- Die Migrationsseite warnt beim Umstieg ausdrücklich vor „excessive randomness or excessive conservatism" — nach der Migration Sampling und Antwortlänge gegenprüfen, statt alte Werte zu übernehmen.

## Output- & Format-Konventionen
- 1.000.000 Tokens Kontextfenster, `max_tokens` bis 128K; Input Text, Output Text.
- Sampling-Defaults: `temperature` 1.0 (Bereich 0.0–1.0), `top_p` 0.95 (Bereich 0.01–1.0), `do_sample` `true`; `stop`: das Schema erlaubt 4 Einträge, laut Parameterbeschreibung wird derzeit aber nur ein Stop-Wort unterstützt („Currently, only one stop word is supported").
- Structured Output über `response_format: {"type": "json_object"}` (Default `"text"`); Function Calling über `tools` (max. 128 Funktionen), `tool_choice` ausschließlich `"auto"` („only auto is supported") — erzwungene oder benannte Tool-Wahl ist nicht verfügbar.
- Streaming von Tool-Calls braucht `stream=true` **und** `tool_stream=true`; die Argumente kommen inkrementell und müssen aus `delta.tool_calls[*].function.arguments` selbst zusammengesetzt werden.
- Preis pro MTok: Input $1.40, Cached Input $0.26, Output $4.40; Cached-Input-Storage derzeit kostenlos (Stand 2026-10-13).
- Über Mistrals API (`zai-glm-5-3`) kommt `message.content` immer als Chunk-Liste (Thinking + Text) zurück, unabhängig vom `reasoning_effort` — es gibt dort keinen Plain-String-Modus; `reasoning_effort` dort `low`/`high`/`max`, nicht `none`.
- Release-Notes-Eintrag: 2026-08-18. Modellkarte: 753B Parameter (Architektur-Tag `glm_moe_dsa`; aktive Parameter nicht angegeben, unbelegt).

## Migrations-Hinweise
- **VON glm-5.3 weg**: Zielmodelle ohne erzwungenes Thinking brauchen wieder ein explizites Thinking-Setup (Toggle, Budget oder Effort-Feld des Ziels) — sonst läuft ein 5.3-Prompt dort ohne Reasoning; `reasoning_effort: max` nicht blind übernehmen, die Skalen anderer Anbieter sind anders geschnitten; `clear_thinking`, `tool_stream` und das `reasoning_content`-Handling entfernen bzw. auf die Zielkonventionen mappen; explizite Verifikations- und Schritt-für-Schritt-Anweisungen wieder ergänzen, wenn das Ziel nicht per Default tief denkt; 1M-Kontext- und 128K-Output-Annahmen gegen das kleinere Zielfenster prüfen; `response_format: {"type": "json_object"}` durch das Structured-Output-Format des Ziels ersetzen.
- **ZU glm-5.3 migrieren**: (1) **Breaking**, offizieller Wortlaut: „If your application currently uses `thinking.type: "disabled"`, please change it to `enabled` and set `reasoning_effort` to `low` before updating the model ID to `glm-5.3`. Otherwise, the request will fail." Jeder Non-Thinking-Schnellpfad wird zu `enabled` + `low`. (2) `reasoning_effort`-Werte aus der GLM-5.2-Ära (`none`, `minimal`, `medium`, `xhigh`) entfernen — dort wurden sie gemappt, hier sind sie auf der Standard-API ein Fehler; beim Self-Hosting gibt es keinen Fehler, sondern einen stillen Fallback auf `max` — `none`/`minimal` daher nie als „aus" übernehmen, sondern explizit `low` setzen. (3) `model` auf `"glm-5.3"` setzen und `max_tokens` an das 128K-Limit anpassen. (4) `temperature` 1.0 / `top_p` 0.95 als Ausgangspunkt, danach nur einen der beiden Werte tunen. (5) Streaming-Tool-Calls auf `tool_stream=true` plus Argument-Konkatenation umstellen. (6) Mehr-Turn-Verläufe um `reasoning_content` erweitern und `clear_thinking=false` setzen, wenn die Reasoning-Kette über Turns tragen soll. (7) Multimodale Routen schlagen fehl — Bild-Eingaben auf `glm-5.3-flash` legen, das laut Release Notes native visuelle Fähigkeiten hat. (8) Nach der Umstellung die offizielle Verifikations-Checkliste abarbeiten: Antwortqualität, Randomness/Konservatismus, Tool-Streaming sowie Latenz und Kosten unter langem Kontext und tiefem Thinking. (9) Mehrere Stop-Sequenzen auf eine reduzieren; `tool_choice`-Werte außer `auto` entfernen (ein Ersatz für erzwungene Tool-Wahl ist nicht dokumentiert, unbelegt).
