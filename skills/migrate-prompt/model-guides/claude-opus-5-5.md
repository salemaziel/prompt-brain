# Claude Opus 5.5

## Reasoning / Thinking
- Type: **adaptive, always on**. Omit `thinking` or send `{type: "adaptive"}` (equivalent). `{type: "disabled"}` and `{type: "enabled", budget_tokens: N}` return 400 `invalid_request_error` (`"thinking.type.disabled" is not supported for this model. …`) at **every** effort level — Opus 5 still accepts `disabled` up to effort `high`.
- Depth exclusively controlled via `output_config.effort` (`low | medium | high | xhigh | max`), **default `medium`** (Opus 5 and older Opus: `high`) — a request without `effort` runs one tier lower than on Opus 5. Effort level names do not correspond to the same amount of thinking across models: according to Anthropic tests, `medium` on coding and knowledge work matches or exceeds Opus 5 on `high`; at the same tier, Opus 5.5 thinks more per turn than Opus 5, most noticeably at `xhigh`/`max`.
- **Per-message effort** (beta `mid-conversation-output-config-2026-07-01`; Claude API, Google Cloud, and Amazon Bedrock): a `role: "system"` message with empty `content` and `output_config.effort` changes the level mid-conversation while preserving the prompt cache. Changing top-level `effort` between requests invalidates the cache.
- `thinking.display` default `"omitted"` (empty thinking fields); `"summarized"` returns a summary; `"updates"` (beta `thinking-display-updates-2026-08-18`) returns only progress notes between tool calls.
- **Thinking blocks are bound to model and conversation**: Opus 5.5 reads blocks from Opus 5 and older Opus, Sonnet, and Haiku models (on Claude API and Google Cloud also from Sonnet 5.5 and Haiku 5.5), but not from Fable or Mythos models; Opus 5.5 blocks are read only by Fable 5.1 and Mythos 5.1 (Claude API). Non-readable blocks are discarded without error and not billed. Modifications to `system`, `tools`, or earlier messages preceding a block → 400 on replay (default for accounts created on or after August 31, 2026); `thinking-binding-controls-2026-08-01` plus `prefix_mismatch_behavior: "drop_block"` discards instead.
- Non-default values for `temperature`/`top_p`/`top_k` → 400 (`top_p` default 0.99; `temperature` and `top_p` together → 400 even on default values).
- `max_tokens` is a hard limit across thinking **plus** response text; start with 64k at `xhigh`/`max`; for long agentic coding turns, 128k (the maximum) has proven effective according to docs.

## Prompting Style
- Existing **Opus 5 prompts run well without changes according to Anthropic**; Opus 5 patterns remain a sound starting point. Simply incorporate the deltas.
- **Effort instead of prompt**: set effort explicitly and re-sweep rather than adopting the Opus 5 value; achieve less thinking primarily through a lower level (more reliable than prompt instructions); use `xhigh`/`max` only with measured quality gains.
- **Prompts for disabled thinking** (Opus 5 routes with `disabled`): start at `low` and evaluate, move to `medium` if quality drops; under latency pressure, optionally use "Answer directly without deliberating."; remove rules prohibiting thinking; review need for Opus 5 anti-artifact instructions (sentence before tool call, no internal tags).
- **Do not request reasoning in the response text**: prompts, skills, and tool descriptions that prompt the model to write out thinking/reasoning (`<thinking>`/`<reasoning>`/scratchpad sections, `reasoning`/`thinking`/`trace` fields in JSON or tool input, reasoning logs, "verbatim"/"in full") can be rejected with `stop_reason: "refusal"` and `stop_details.category: "reasoning_extraction"`. Instead, request brief rationales, evidence, or a summary of steps; if reasoning is needed, read `display: "summarized"`. No fallback model exists for this category — modify prompt instead of resending.
- **Unattended agent loops**: The model reports along the way and sometimes ends turns with plain text (`end_turn`). Treat text-only turns as progress reports rather than completion, maintain subtasks in a checklist, and follow up on open items with a short user message (at most two to three automatic continuations). Optionally add a system prompt clause explicitly naming unwanted stop types — from the first request, avoid in human-in-the-loop apps, retain confirmation for risky actions.
- **Progress updates**: describe cadence and format in the system prompt (e.g. statement of intent before the first tool call, brief recap at the end); declare a message tool from the first request for verbatim handoffs; append a turn-scoped reminder on long quiet stretches (`clear_at: "next_user_message"`, beta `mid-conversation-system-clear-at-2026-08-21`).
- **Multi-app workflows**: Opus 5.5 starts working quickly — a sentence requiring broad exploration of all relevant sources before taking action (including unmentioned ones) improves the success rate; keep untrusted content out of searched sources.
- **Chat**: remove "think carefully" lines (effort is the lever); optionally instruct the model to treat answered questions as resolved (not for long analyses or agentic tasks).
- **Multi-agent harnesses**: a time budget with elapsed time (`elapsed 340s / 1200s`) or a time-matters sentence speeds up teams; the budget is advisory only.
- **Pasted text**: wrap in `<pasted_content id="…">` tags with random IDs plus a system prompt note to follow instructions within only at user request. **Frontend**: name concrete patterns to avoid rather than "no generic AI look".

## Strengths & Weaknesses (prompt-relevant)
- Strengths: agentic coding and code review in real-world repositories (at `medium`, on par with or better than Opus 5 on `high` according to Anthropic tests, with fewer steps and tokens; more bugs found with fewer false alarms); hour-long autonomous runs with parallel subagents; knowledge work (fewer incorrect figures or citations, financial modeling, detail extraction from large inputs); clear reporting; more precise reading of charts, diagrams, and screenshots without tools; more reliable computer use. Generates output tokens over 30% faster than Opus 5 and often requires fewer tokens per task. Resists indirect prompt injection better than any prior Opus model.
- Weaknesses / quirks: thinks more than Opus 5 at the same tier; sometimes terminates long tasks prematurely with a status report; re-evaluates earlier answers in multi-turn chats (latency); jumps into vaguely specified multi-app tasks without exploration; defaults to a few recurring frontend styles; dense visual inputs still benefit from higher resolution and crop/zoom tools.
- Safety classifiers for `bio` (new compared to Opus 5), `cyber`, and `reasoning_extraction`; vulnerability discovery in source code is permitted.

## Output & Format Conventions
- 1M context window as default (no beta header), 128k output tokens; up to 300k via Message Batches API with beta header `output-300k-2026-03-24`. Input: text and images, output: text.
- Responses may start with `thinking` blocks: read content blocks by `type` instead of `content[0].text`; in tool loops, return all thinking blocks unmodified (including empty ones) — edited, reordered, or partially removed blocks → 400.
- **Text between tool calls** arrives as a progress `thinking` block (at most one before each tool call) instead of `text`; empty by default under `display: "omitted"`, causing a text-only UI to appear silent → set `display: "updates"` or `"summarized"`.
- **Forced tool use is discontinued**: `tool_choice` `any`/`tool` → 400 `tool_choice: type "tool" and "any" are not supported for this model.` (also on token counting endpoint). Replacement: `auto` plus `strict: true` or Structured Outputs, specifying in the prompt when the tool applies; on Amazon Bedrock (no Structured Outputs), use `auto` without `strict` and validate tool input in application code.
- No assistant prefill (400) — use Structured Outputs or system prompt instructions on Bedrock.
- Computer Use on Claude API and Google Cloud only as `computer_toolset_20260801` (without beta header); `computer_20251124` → 400 `'claude-opus-5-5' does not support tool types: computer_20251124.`; unchanged on Bedrock.
- Refusals: HTTP 200 with `stop_reason: "refusal"` and `stop_details` — inspect before reading `content`. `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`, Claude API only) retries on the recommended model, but not for `reasoning_extraction`. Refusals before any output are billed for `bio`, `frontier_llm`, and `reasoning_extraction`.
- Mid-conversation system messages (`role: "system"` directly after a user turn, no beta header) on Claude API, Bedrock, and Google Cloud — tool to maintain append-only history.
- Pricing per MTok: input $4, output $20, 5m cache write $5, 1h cache write $8, cache read $0.20 (0.05× input); batch 50% discount. Minimum cacheable prefix: 512 tokens. Tokenizer since Opus 4.7: roughly 1×–1.35× as many tokens as models prior to that.
- Model IDs: `claude-opus-5-5` (Claude API, Google Cloud, Microsoft Foundry, Claude Platform on AWS), Bedrock `anthropic.claude-opus-5-5`. Status *Active (latest)*, release September 22, 2026, retirement not before September 22, 2027; reliable knowledge cutoff Jun 2026. Priority Tier not supported; Fast Mode (Research Preview, Claude API only) with `speed: "fast"` and `fast-mode-2026-02-01`.

## Migration Notes
- **MIGRATING FROM claude-opus-5-5**: Opus 5.5 thinking blocks are read only by Fable 5.1/Mythos 5.1 (Claude API) — on any other target, subsequent turns execute without prior reasoning. Check the target model's default effort (Opus 5: `high`) and re-sweep effort. Forced tool use and `thinking: {type: "disabled"}` are possible again on Opus 5 (there up to effort `high`); narration between tool calls returns as `text` there. Retain beta specifics (`display: "updates"`, turn-scoped system messages, per-message effort) only if documented by the target guide. Review Opus 5.5 compensations (continuation nudge, exploration directive, time budget, pasted content tags) against the target.
- **MIGRATING TO claude-opus-5-5**:
  - Specifically **from claude-opus-5**: Swap model ID; remove `thinking: disabled`/`enabled` and select effort (where thinking was off, choose a lower tier); set `effort` explicitly; replace forced `tool_choice` values; migrate Computer Use to the toolset; read content blocks by `type` and return thinking blocks unmodified; keep history append-only (modify `system`/`tools` via mid-conversation system messages); switch progress UI to `display: "updates"`; expand refusal handling for `bio`; replace reasoning-in-response-text instructions; re-measure costs and latency at selected tier.
  - Specifically **from claude-opus-4-8 or older**: Additionally, requests without a `thinking` field now always think — re-budget `max_tokens` (thinking plus text) and output costs, treating the thinking field solely as display text; cache minimum drops to 512 (Opus 4.8: 1024); Priority Tier is discontinued. From 4.7 or older: fresh effort sweep, remove context beta headers. From 4.6 or older: remove `temperature`/`top_p`/`top_k` and `budget_tokens`, recalibrate costs and `max_tokens` for the new tokenizer, review image budget for high-resolution images (up to ~3× image tokens), remove progress scaffolding.
  - Specifically **from claude-sonnet-5**: The Opus 5 path applies unchanged; additionally, mid-conversation system messages are now available and cache minimum drops from 1024 to 512 tokens.
