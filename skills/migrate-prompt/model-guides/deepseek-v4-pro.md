# DeepSeek-V4-Pro

## Reasoning / Thinking
- Hybrid model under a single model ID: Thinking is **active by default** with effort `high`. OpenAI format: `thinking: {"type": "enabled"|"disabled"}` (via `extra_body`) plus `reasoning_effort` `low|high|max` (`medium`/`xhigh` map to `high`); Anthropic format: same toggle `thinking: {"type": "enabled"|"disabled"}` (`budget_tokens` is ignored), effort via `output_config: {"effort": "low|high|max"}`; Responses API: `reasoning: {"effort": "none|low|high|max"}` (`none` = off). `reasoning_effort` also accepts `none` (thinking off); mapping: minimal → low, medium/xhigh → high, ultra → max. The Model Card names the levels Non-Think / Think High / Think Max; **for Think Max, a context window of at least 384K tokens is recommended**, and a prefix is prepended to the system prompt ("Reasoning Effort: Absolute maximum with no shortcuts permitted. You MUST be very thorough in your thinking …") — the prompt then competes with a thoroughness instruction; request concise answers explicitly if needed.
- `reasoning_content` is returned alongside `content`. In pure multi-turn conversations it may be omitted (the API ignores it); **across tool-call turns, it must** be passed back.
- Thinking mode ignores `temperature`, `presence_penalty`, and `frequency_penalty` (no error, no effect). `top_p` takes effect only in thinking mode (effectively 0.95–1.0, lower values → 0.95); in non-thinking mode, `top_p` is fixed at 1.0.

## Prompting Style
- Prompt contract is identical to V4-Flash (same API guides, same chat template). System prompt is encoded directly after BOS: `<｜begin▁of▁sentence｜>{system}<｜User｜>{user}<｜Assistant｜>` — system instructions sit at the very beginning and are not a separate block.
- Prefix caching runs automatically and matches only on **full** prefix matches of a cache unit (best-effort, no hit rate guaranteed): place stable instructions and reference material upfront, variable input at the end (inferred from examples — (unbelegt)).
- JSON: `response_format: json_object` **plus** the literal "json" and an example JSON in the system or user prompt; set `max_tokens` generously. No `json_schema` type is documented — structure is prompt-guided, not schema-enforced.
- Prefill via Chat Prefix Completion: last message `role: "assistant"` + `prefix: True` against `https://api.deepseek.com/beta`, optionally with `stop`. Local deployment: `temperature = 1.0`, `top_p = 0.95` agentic / otherwise 1.0 (0813 card); for `high`/`max`, 384K max output is recommended.
- Tool calls are emitted in DSML markup (`<｜DSML｜tool_calls>` / `<｜DSML｜invoke>`) with `string="true"` for raw strings and `string="false"` for JSON-typed values. Since 2026-09-10, DeepSeek ranks V4.1-Flash ahead of V4-Pro ("ahead of V4-Pro on performance, cost, speed & total runtime"); Pro remains primarily relevant for knowledge-heavy prompts (Base SimpleQA-Verified 55.2 vs. 42.3 on V4.1-Flash-Base).

## Strengths & Weaknesses (prompt-relevant)
- Strengths: Frontier tier (MoE 1.6T total / 49B active, hybrid attention composed of Compressed Sparse Attention + Heavily Compressed Attention, Manifold-Constrained Hyper-Connections, Muon optimizer, >32T training tokens). Benchmarks (Think Max): LiveCodeBench 93.5, Codeforces 3206, IMOAnswerBench 89.8, GPQA Diamond 90.1, MMLU-Pro 87.5, SimpleQA-Verified 57.9, MRCR 1M 83.5 — strong in coding, competitive math/science, factual knowledge, and 1M retrieval. Efficiency: 27% of single-token inference FLOPs and 10% of KV cache of V3.2 at 1M context.
- Weaknesses: Throughput and pricing trade-offs rather than capability — price per 1M tokens (Peak / Off-Peak): input cache miss $1.32 / $0.66, cache hit $0.044 / $0.022, output $3.96 / $1.98 — approx. 4.4× (input) and 3.3× (output) `deepseek-flash`; 500 instead of 2500 concurrent requests; Peak = Mon–Fri 01:00–04:00 and 06:00–10:00 UTC. JSON mode occasionally produces empty `content`; FIM completion is non-thinking only; V4-Pro does not accept images (vision "Not supported"); document blocks are not supported on the Anthropic endpoint; Anthropic endpoint lacks `anthropic-beta`/`anthropic-version` headers, lacks `top_k`, MCP, and containers. The Model Card contains no explicit limitations section.

## Output & Format Conventions
- 1M context window, up to 384K output tokens. Current version behind the ID: DeepSeek-V4-Pro-0813 (GA on 2026-08-13 for APP, Web, and API); invocation path unchanged — continue using `deepseek-v4-pro` for the latest version. The re-routing to V4.1-Flash announced on 2026-09-10 for 2026-09-14 was rescinded according to the change log — V4-Pro continues to run with unchanged billing; a V4.1-Pro has been announced, release date (unbelegt).
- Base URLs: `https://api.deepseek.com` (OpenAI SDK), `https://api.deepseek.com/anthropic` (Anthropic SDK, `claude-opus*` → `deepseek-v4-pro`), `https://api.deepseek.com/beta` (Prefill); Responses API native (adapted for Codex).
- `response_format` `text|json_object`; `tool_choice` none/auto/required/specific — `required` and named tools return HTTP 400 in thinking mode (only usable with `thinking: disabled`); `max_tokens` default: 8K (Non-Thinking) / 64K (Thinking) / 128K (`max`), maximum 384K; up to 16 stop sequences; `top_logprobs` 0–20; `temperature` 0–2 (default 1), `top_p` 0–1 (default 1); `frequency_penalty`/`presence_penalty` deprecated and ineffective. Peak / Off-Peak billing since 2026-08-16 16:00 UTC (Off-Peak = half of peak price).

## Migration Notes
- **MIGRATING FROM deepseek-v4-pro**: Remove `thinking`/`reasoning_effort` and all `reasoning_content` wiring; if target lacks a native reasoning mode, write explicit CoT instructions back into prompt; if target supports `json_schema`, convert in-prompt JSON examples into genuine schemas and remove mandatory literal "json"; translate DSML tool-call examples into target's tool format; replace `prefix: True` with prefill or stop-sequence equivalent; 1M/384K limits are not portable — plan for chunking again.
- **MIGRATING TO deepseek-v4-pro**: From `deepseek-chat`/`deepseek-reasoner` (decommissioned since 2026-07-24 15:59 UTC), the rule "keep base_url, just update `model` to `deepseek-v4-pro`" applies — however, legacy IDs routed to **Flash**, so Pro is a deliberate upgrade. Prompt deltas: (1) former `deepseek-chat` prompts now explicitly require `thinking: {"type": "disabled"}`, as thinking is default on; (2) remove `frequency_penalty`/`presence_penalty`; (3) remove temperature tuning from reasoning prompts — dead text in thinking mode (`top_p` operates only between 0.95 and 1.0 there); (4) pass back `reasoning_content` in tool loops instead of stripping CoT; (5) delete chunking / map-reduce scaffolding designed for old V3/R1 windows and pass full documents; (6) move static instructions upfront (prefix caching; inferred from examples — (unbelegt)); (7) map prompt-text depth directives ("think step by step", "be thorough") to `reasoning_effort: low|high|max`; (8) tool enforcement via `tool_choice: required` or named tool is allowed only with `thinking: {"type": "disabled"}` — otherwise 400.
- **Pro ↔ Flash (`deepseek-flash` = V4.1-Flash)**: Identical API parameters and 1M/384K context/output limits, but templates are no longer identical (V4.1: DSML tags with leading whitespace, numerical effort 1–100, mid-conversation system messages), and only Flash accepts images. Anthropic endpoint: Flash supports mid-conversation system messages (`in-history`), while Pro only supports leading ones (`leading-only`) — when switching to Pro, consolidate system updates into the leading system message. Agentic coding prompts perform better on V4.1-Flash according to vendor benchmarks (TB 2.1 90.6 vs. 87.9, DeepSWE v1.1 74.2 vs. 62.7); reserve Pro primarily for knowledge-heavy prompts.
