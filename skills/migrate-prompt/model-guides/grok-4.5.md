# Grok 4.5

## Reasoning / Thinking
- Typ: **nicht abschaltbar**. Die Reasoning-Seite sagt ausdrücklich „Reasoning cannot be disabled" — einen `none`-Pfad wie bei grok-4.3 gibt es hier nicht.
- Belegte Leiter (Reasoning-Seite, Release Notes): `reasoning.effort` bzw. `reasoning_effort` = `low | medium | high`, **Default `high`** („If not specified, `reasoning_effort` defaults to `high`."). Wer den Parameter nicht setzt, fährt permanent die teuerste belegte Stufe.
- **`xhigh`: widersprüchlich dokumentiert.** Die Reasoning-Seite nennt grok-4.5 wörtlich als Modell, bei dem `xhigh` still als `high` behandelt wird („On models that do not support it, such as `grok-4.5`, requests with `xhigh` are treated as `high`."), die Modellseite listet `xhigh` inzwischen als unterstützt. Effektives Verhalten (unbelegt); `xhigh` auf 4.5 nicht als zusätzliche Tiefenstufe einplanen — eine stille Herabstufung käme ohne Fehler und ohne Warnung.
- **Keine Reasoning-Summaries.** Zusammenfassungen des internen Denkwegs exponiert xAI nur für grok-4.7. Für grok-4.5 existiert ausschließlich verschlüsselter Reasoning-Inhalt über `include: ["reasoning.encrypted_content"]`, der unverändert in Folge-Requests zurückgespielt werden kann — nichts davon ist für Menschen oder einen Downstream-Parser lesbar.
- Reasoning-Tokens werden mitabgerechnet („the reasoning tokens are billed as part of your total consumption").
- `presencePenalty`, `frequencyPenalty` und `stop` sind für Reasoning-Modelle gesperrt: „Requests that include them return an error." Formatsteuerung darf also nicht über Stop-Sequenzen laufen.

## Prompting-Stil
- Positionierung laut Modellseite: „SpaceXSI's intelligent coding model for agentic software, engineering, and workflow tasks." Entsprechend **agentisch und aufgabenorientiert** prompten — Coding-, Tool- und Workflow-Arbeit, kein Allzweck-Chat-Profil.
- Das Announcement betont, dass 4.5 End-to-End-Anwendungen „from single prompts with minimal specification" baut: die Aufgabenbeschreibung darf knapp bleiben, aber **Akzeptanzkriterien, Zielstack und Abbruchbedingungen gehören trotzdem in den Prompt** — sonst entscheidet das Modell sie selbst.
- Die Auswahl-Logik gehört in die **Tool-Definitionen**, nicht in Prosa: „What the tool does — helps the model decide when to use it." Paralleles Tool-Calling ist per Default aktiv (`parallel_tool_calls: false` schaltet es ab), `tool_choice` kennt `auto` (Default) / `required` / `none` / erzwungene Funktion. Ein `parameters`-Root, der weder Objekt noch Objekt-Union ist, wird mit `400` abgelehnt.
- Format über **Structured Outputs** erzwingen (`response_format.type: "json_schema"`): „the response is guaranteed to match your schema." Grenzen einplanen — String-Constraints bis 2.048 Zeichen, Arrays bis 256 Einträge, max. 64 Object-Properties; `not` sowie `if`/`then`/`else` gelten nur als Best-Effort.
- Prompt-Caching läuft automatisch ab dem Anfang des `messages`-Arrays. Den statischen Teil (System-Prompt, Tool-Definitionen) **vorn und unverändert** halten und `x-grok-conv-id` (Chat Completions/gRPC) bzw. `prompt_cache_key` (Responses API) mitschicken, damit die Requests einer Konversation auf denselben Server geroutet werden — Cache-Einträge liegen pro Server.
- Eine modellspezifische Prompting-Guidance publiziert xAI für grok-4.5 nicht (eine eigene Developer-Seite gibt es nur noch für grok-4.7; `/developers/grok-4-5` leitet dorthin um). Jede darüber hinausgehende Stilaussage ist unbelegt.

## Stärken & Schwächen (prompt-relevant)
- Stärken: ausgeprägtes **Coding-/Agenten-Profil** (Rust und C/C++ werden im Announcement eigens genannt); hohe **Token-Effizienz** — laut Announcement rund 4,2× weniger Output-Tokens als Opus 4.8 (max) bei Software-Engineering-Aufgaben und „twice greater token efficiency" gegenüber vergleichbaren Modellen, bei etwa 80 TPS; Office-Artefakte (mehrblättrige Excel-Modelle mit Formeln und Web-Recherche, PowerPoint-Diagramme, Word-Prosa); volle Flaggschiff-Durchsatzdecke (150 rps / 50M tpm, identisch zu grok-4.6/4.7); günstigster Cached Input der 4.5/4.6/4.7-Klasse ($0.30 statt $0.50 unter 200k); Function Calling und Structured Outputs beide ja.
- Vom Hersteller genannte Benchmarks (nicht unabhängig verifiziert): DeepSWE 1.0 62,0 %, SWE Bench Pro 64,7 %, Terminal Bench 2.1 83,3 %, SWE Marathon 29,0 %.
- Schwächen/Eigenheiten: **`xhigh` widersprüchlich dokumentiert** und **kein abschaltbares Reasoning** — die belegte Effort-Spanne ist schmaler als bei den Nachbarn; keine lesbaren Reasoning-Summaries; **Batch API „Not supported"** (grok-4.3 gewährt dort 20 % Rabatt); laut Modellseite nur Regionen us-east-1 und us-west-2, **keine EU-Region** (die Release Notes melden im Juli lediglich Verfügbarkeit „in the API console for EU users"); **Preisklippe bei 200k Prompt-Tokens** — ab da gilt der doppelte Satz für ALLE Tokens des Requests; **kein publizierter Knowledge Cutoff** und kein publiziertes Output-Limit; auf der Modellübersicht empfiehlt xAI für Code und Chat ausdrücklich grok-4.7, nicht 4.5.

## Output- & Format-Konventionen
- 500.000 Tokens Kontextfenster; Input Text + Bild, Output nur Text. Max. Output-Tokens: nicht publiziert (unbelegt). Knowledge Cutoff: nicht publiziert (unbelegt) — die Übersicht nennt nur den Cutoff von grok-4.7 (Mai 2026).
- Function Calling: ja; Structured Outputs: ja; Reasoning: ja; Batch API: „Not supported".
- Preise pro 1M Tokens: Input $2.00 (<200k Prompt) / $4.00 (≥200k), Cached Input $0.30 / $0.60, Output $6.00 / $12.00. Rate Limits: 150 Requests/s, 50M Tokens/min; Regionen us-east-1, us-west-2.
- Auf der Modellseite dokumentierte Aliase: `grok-4.5-latest` **und** `grok-build-latest`. `grok-build-latest` benennt keine Generation, ist also ein rollender Zeiger — Default-Modell von Grok Build ist laut Developer-Seite inzwischen grok-4.7; nicht als stabilen Pin auf 4.5 verwenden.
- Freigabe am 16. Juli 2026 laut offiziellem Announcement (einzige belastbare Datumsquelle). Die Release-Notes-Seite listet den Eintrag nur unter der Monatsüberschrift „July" **ohne Jahresangabe** und taugt deshalb nicht als Datumsquelle.

## Migrations-Hinweise
- **VON grok-4.5 weg** (zu grok-4.7, von xAI für Code und Chat empfohlen, oder zu grok-4.6): `xhigh` wird dort laut Reasoning-Seite real ausgeführt statt still auf `high` gefaltet — Kosten und Latenz neu messen, bevor der Wert übernommen wird; Cached Input steigt von $0.30 auf $0.50 (<200k), Standard-Input/Output bleiben identisch. Kontext (500k), Rate Limits und die fehlende Batch-Unterstützung bleiben gleich; als Regionen kommen us-central-1 und der US-Regional-Endpoint `https://us.api.x.ai/v1` (+10 %) hinzu, eine EU-Region gibt es weiterhin nicht. Nur bei grok-4.7 sind Reasoning-Summaries dokumentiert, und auf der Responses API kommt `reasoning.encrypted_content` dort bei jeder Antwort zurück — Reasoning-Items unverändert im nächsten `input` zurückschicken. Geht es stattdessen zu grok-4.3: dort wieder `reasoning_effort: none` als Zero-Thinking-Pfad vorsehen (Default dort `low`), 1M Kontext und die EU-Region nutzen, Batch-Rabatt einplanen — die Reasoning-Klassenregeln sind für 4.3 allerdings nicht dokumentiert.
- **ZU grok-4.5 migrieren**: (1) Jeden `xhigh`-Wert entfernen oder bewusst auf `high` setzen — laut Reasoning-Seite wird er stumm herabgestuft, und die Prompt-Annahme „tiefstes Reasoning" stimmt nicht mehr. (2) `reasoning_effort` explizit setzen statt auf den Default zu vertrauen: nicht gesetzt bedeutet `high`. (3) Alle Zero-Thinking-Schnellpfade (grok-4.3 `none`, Claude `thinking: disabled`, OpenAI `minimal`) auf `low` heben — Reasoning ist nicht abschaltbar, Latenz- und Kostenbudgets dieser Routen sind neu zu rechnen. (4) `presence_penalty`, `frequency_penalty` und `stop` aus dem Request streichen (sonst Fehler) und die Formatkontrolle vollständig auf Structured Outputs umstellen. (5) Prompt-Prefix stabilisieren und `x-grok-conv-id` bzw. `prompt_cache_key` ergänzen, sonst wird der Cache-Vorteil nicht realisiert. (6) Batch-Jobs umplanen — die Batch API bedient dieses Modell nicht. (7) Chunking vor Kontext-Ausreizen: ab 200k Prompt-Tokens verdoppelt sich der Satz für Input **und** Output des gesamten Requests. (8) Prompts oder Pipelines, die einen sichtbaren Denkweg auswerten, umbauen — hier gibt es nur verschlüsseltes Reasoning. (9) EU-Datenresidenz ist nicht möglich (nur us-east-1/us-west-2). (10) Tool-Definitionen prüfen: paralleles Tool-Calling ist per Default an; wo eine strikte Reihenfolge nötig ist, `parallel_tool_calls: false` setzen.
