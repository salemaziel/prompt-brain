# Grok 4.5

## Reasoning / Thinking
- Type: **cannot be disabled**. The reasoning page explicitly states "Reasoning cannot be disabled" — there is no `none` path here as in grok-4.3.
- Documented ladder (reasoning page, release notes): `reasoning.effort` or `reasoning_effort` = `low | medium | high`, **default `high`** ("If not specified, `reasoning_effort` defaults to `high`."). Leaving the parameter unset permanently runs the most expensive documented level.
- **`xhigh`: contradictorily documented.** The reasoning page literally mentions grok-4.5 as a model where `xhigh` is silently treated as `high` ("On models that do not support it, such as `grok-4.5`, requests with `xhigh` are treated as `high`."), while the model page now lists `xhigh` as supported. Effective behavior (unbelegt); do not plan on `xhigh` on 4.5 as an additional depth level — a silent downgrade would occur without error and without warning.
- **No reasoning summaries.** Summaries of the internal thinking process are exposed by xAI only for grok-4.7. For grok-4.5, only encrypted reasoning content exists via `include: ["reasoning.encrypted_content"]`, which can be passed back unchanged in follow-up requests — none of it is readable for humans or downstream parsers.
- Reasoning tokens are billed ("the reasoning tokens are billed as part of your total consumption").
- `presencePenalty`, `frequencyPenalty`, and `stop` are prohibited for reasoning models: "Requests that include them return an error." Format control must therefore not run via stop sequences.

## Prompting Style
- Positioning according to model page: "SpaceXSI's intelligent coding model for agentic software, engineering, and workflow tasks." Accordingly prompt in an **agentic and task-oriented** manner — coding, tool, and workflow tasks, not a general-purpose chat profile.
- The announcement emphasizes that 4.5 builds end-to-end applications "from single prompts with minimal specification": the task description can remain concise, but **acceptance criteria, target stack, and termination conditions still belong in the prompt** — otherwise the model decides them autonomously.
- Selection logic belongs in the **tool definitions**, not in prose: "What the tool does — helps the model decide when to use it." Parallel tool calling is active by default (`parallel_tool_calls: false` disables it), `tool_choice` supports `auto` (default) / `required` / `none` / forced function. A `parameters` root that is neither an object nor an object union is rejected with `400`.
- Enforce format via **Structured Outputs** (`response_format.type: "json_schema"`): "the response is guaranteed to match your schema." Plan for limits — string constraints up to 2,048 characters, arrays up to 256 items, max 64 object properties; `not` and `if`/`then`/`else` are only best-effort.
- Prompt caching runs automatically from the start of the `messages` array. Keep the static portion (system prompt, tool definitions) **at the front and unchanged** and send `x-grok-conv-id` (Chat Completions/gRPC) or `prompt_cache_key` (Responses API) so requests within a conversation are routed to the same server — cache entries reside per server.
- xAI does not publish model-specific prompting guidance for grok-4.5 (a dedicated developer page only exists for grok-4.7; `/developers/grok-4-5` redirects there). Any stylistic assertion beyond this is unbelegt.

## Strengths & Weaknesses (prompt-relevant)
- Strengths: Pronounced **coding/agentic profile** (Rust and C/C++ are specifically highlighted in the announcement); high **token efficiency** — according to the announcement, approximately 4.2× fewer output tokens than Opus 4.8 (max) on software engineering tasks and "twice greater token efficiency" compared to comparable models, at around 80 TPS; office artifacts (multi-sheet Excel models with formulas and web research, PowerPoint diagrams, Word prose); full flagship throughput ceiling (150 rps / 50M tpm, identical to grok-4.6/4.7); cheapest cached input in the 4.5/4.6/4.7 class ($0.30 instead of $0.50 below 200k); function calling and Structured Outputs both yes.
- Vendor-reported benchmarks (not independently verified): DeepSWE 1.0 62.0%, SWE Bench Pro 64.7%, Terminal Bench 2.1 83.3%, SWE Marathon 29.0%.
- Weaknesses: **`xhigh` contradictorily documented** and **reasoning cannot be disabled** — the verified effort span is narrower than its neighbors; no readable reasoning summaries; **Batch API "Not supported"** (grok-4.3 grants a 20% discount there); according to the model page, only regions us-east-1 and us-west-2, **no EU region** (the release notes in July merely report availability "in the API console for EU users"); **price cliff at 200k prompt tokens** — above that, double rates apply to ALL tokens of the request; **no published knowledge cutoff** and no published output limit; on the model overview, xAI explicitly recommends grok-4.7 for code and chat, not 4.5.

## Output & Format Conventions
- 500,000 tokens context window; input text + image, output text only. Max output tokens: not published (unbelegt). Knowledge cutoff: not published (unbelegt) — the overview lists only the cutoff of grok-4.7 (May 2026).
- Function calling: yes; Structured Outputs: yes; Reasoning: yes; Batch API: "Not supported".
- Prices per 1M tokens: input $2.00 (<200k prompt) / $4.00 (≥200k), cached input $0.30 / $0.60, output $6.00 / $12.00. Rate limits: 150 requests/s, 50M tokens/min; regions us-east-1, us-west-2.
- Documented aliases on the model page: `grok-4.5-latest` **and** `grok-build-latest`. `grok-build-latest` does not designate a generation, making it a rolling pointer — the default model of Grok Build is now grok-4.7 according to the developer page; do not use as a stable pin to 4.5.
- Release on July 16, 2026 according to official announcement (only reliable date source). The release notes page lists the entry only under the month heading "July" **without year** and is therefore not suitable as a date source.

## Migration Notes
- **MIGRATING FROM grok-4.5** (to grok-4.7, recommended by xAI for code and chat, or to grok-4.6): `xhigh` is executed for real there according to the reasoning page instead of being silently folded into `high` — remeasure cost and latency before carrying over the value; cached input increases from $0.30 to $0.50 (<200k), while standard input/output remain identical. Context (500k), rate limits, and lack of batch support remain unchanged; us-central-1 and the US regional endpoint `https://us.api.x.ai/v1` (+10%) are added as regions, with still no EU region. Reasoning summaries are documented only for grok-4.7, and on the Responses API `reasoning.encrypted_content` is returned on every response there — send reasoning items back unchanged in the next `input`. If migrating to grok-4.3 instead: provide for `reasoning_effort: none` as a zero-thinking path (default is `low` there), utilize 1M context and the EU region, plan for batch discount — note that reasoning class rules are not documented for 4.3, however.
- **MIGRATING TO grok-4.5**: (1) Remove any `xhigh` value or consciously set it to `high` — according to the reasoning page it is silently demoted, and the prompt assumption of "deepest reasoning" no longer holds. (2) Set `reasoning_effort` explicitly rather than relying on the default: unset means `high`. (3) Elevate all zero-thinking fast paths (grok-4.3 `none`, Claude `thinking: disabled`, OpenAI `minimal`) to `low` — reasoning cannot be disabled; latency and cost budgets for these routes must be recalculated. (4) Remove `presence_penalty`, `frequency_penalty`, and `stop` from the request (otherwise error) and shift format control entirely to Structured Outputs. (5) Stabilize prompt prefix and include `x-grok-conv-id` or `prompt_cache_key`, otherwise the cache benefit is not realized. (6) Reschedule batch jobs — the Batch API does not serve this model. (7) Prioritize chunking over exhausting context: above 200k prompt tokens, the rate doubles for input **and** output of the entire request. (8) Rebuild prompts or pipelines that evaluate a visible thinking trace — only encrypted reasoning exists here. (9) EU data residency is not possible (only us-east-1/us-west-2). (10) Check tool definitions: parallel tool calling is enabled by default; where a strict sequence is required, set `parallel_tool_calls: false`.
