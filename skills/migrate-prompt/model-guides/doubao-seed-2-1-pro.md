# Doubao Seed 2.1 Pro

## Reasoning / Thinking
- Typ: **Deep Thinking enabled by default**. `thinking.type` platform-wide supports `enabled | disabled | auto`, but `doubao-seed-2-1-pro-260915` and `-260628` appear in the support list only with `enabled` (default) and `disabled` — **no `auto`** (no model in the current support list includes `auto`; `doubao-seed-1-6-250615` has been shut down since 2026-09-21). A request without a `thinking` field triggers reasoning.
- Depth via `reasoning_effort` (Chat API) or `reasoning.effort` (Responses API). All seven levels are accepted: `none | minimal | low | medium | high | xhigh | max`; **default `high`**. Compatibility mapping per documentation: `minimal` disables thinking, `none` maps to `minimal`, **`xhigh`/`max` map to `high`** — above `high` there is no genuine added depth, only silent fallback without error.
- Two ways to disable thinking: `thinking: {"type":"disabled"}` or `reasoning_effort: "minimal"` / `"none"`.
- **Thinking Summary is active by default** (verified for evolving, 2.1-pro-260915, 2.1-lite-260915, 2.1-pro-260628, 2.1-turbo-260628, 2.0-lite-260428): The raw chain-of-thought is not output; instead, `choices.message.reasoning_content` (summary) and `choices.message.encrypted_content` (encrypted original) are returned. `reasoning_effort` affects only the raw thought chain, not the summary; billing is via `usage.completion_tokens_details.reasoning_tokens` based on raw tokens.
- According to documentation, the summary generates noticeably higher packet latency — increase `timeout` and configure clients accordingly.
- Tool calling: **Pass back `encrypted_content`**, it takes precedence over `reasoning_content` and must be unmodified. Returning only `reasoning_content` degrades inference quality in multi-turn/agent runs per documentation; returning neither raises no error. In the Responses API, `previous_response_id` handles this automatically.
- Max reasoning chain 256k tokens — counts against the same output budget as the response.

## Prompting Style
Volcengine documents explicit "Prompt Optimization Recommendations" for Deep Thinking models; they invert conventional prompting instincts:
- **Goal, scenario, and audience instead of task**: Beyond the raw question, add language/tooling requirements (English, Python), target audience (primary school students, executive report), scenario (term paper, topical report, screenplay), and goal (demonstrate domain expertise).
- **Omit task decomposition**: Step-by-step instructions and examples should be reduced or avoided per documentation — they constrain the model's internal reasoning logic. Inherited CoT scaffolding and few-shot blocks are actively harmful here, not merely redundant.
- **Reduce system prompts**: The documentation recommends providing all prompt information directly within the user prompt (`role: user`). This is the most pronounced deviation from other providers' role-separation practices.
- **Format via API, not prose**: Work with `response_format` (`json_schema`, `strict: true`) and avoid emphasizing "output JSON" or repeating schema structures in the prompt — documentation terms this contradictory and redundant; describe the required content instead.
- **Omit `frequency_penalty`/`presence_penalty`** when Structured Output is active — documentation warns twice against anomalous outputs.

## Strengths & Weaknesses (prompt-relevant)
- Strengths:
  - According to capability table: Deep Thinking, text generation, multimodal understanding (input text, image, video; output text), **GUI task execution**, tool calling, and Structured Output. Full tool stack: Function Calling (Chat + Responses), Knowledge Base, MCP, Web Search plugin, Image Processing, and Doubao Assistant (the last five only via the Responses API).
  - Positioning per ByteDance announcement: Agent reliability across multi-step workflows (project planning, document processing, tool usage), end-to-end coding delivery across the enterprise cycle (requirements analysis, implementation, bug fixing, setup, validation), and multimodality. Seed2.1 Pro achieved top scores on GDPVal, top-tier on Agents' Last Exam, and highest marks on CharXiv-RQ and MeasureBench (document/chart/numerical understanding); on TVBench and TOMATO, the blog specifically notes only top-tier levels ("industry-leading levels"), not absolute maximums. The MobileWorld top score and 16% fewer steps on average to task completion are attributed to the "Seed2.1" series as a whole, not specifically the Pro variant. The 260915 release note highlights stronger autonomous planning, long-chain execution, and dynamic self-repair.
- Weaknesses:
  - **Rate limits 500 RPM / 1,000,000 TPM** — the 2.0 generation and Seed 2.1 Lite operate at 30,000 RPM / 5,000,000 TPM, a substantial throughput drop when moving up.
  - **Default response length 4k** despite 256k ceiling.
  - Structured Output is explicitly in **beta** (availability fluctuates, production use only after validation) and cannot be used with TPM guarantee packages.
  - No `auto` thinking, no effort level above `high`. No official knowledge cutoff published (unbelegt).
  - Availability: Pro is documented only on Volcengine Ark (China). On BytePlus ModelArk (international), the 2.1 series lists exclusively `dola-seed-2-1-turbo-260628` — a Pro variant is not documented there.

## Output & Format Conventions
- Model ID: `doubao-seed-2-1-pro-260915` (Ark: 首推, per model page identical to the doubao-seed-evolving state from 2026-09-09); `doubao-seed-2-1-pro-260628` is listed only under past models (往期模型). 260915: Context window 1024k, max input 1024k (260628: 256k/256k); both max response 256k with **default 4k**, max reasoning chain 256k. `doubao-seed-evolving` is a rolling ID updated at least weekly — pin the dated snapshot for reproducible migrations. The undated form `doubao-seed-2.1-pro` appears only as a billing identifier on the pricing page; its status as a callable model ID is not verified (unbelegt).
- Output length via `max_completion_tokens` (Chat API) or `max_output_tokens` (Responses API) — the limit covers reasoning chain **plus** response.
- Structured Output: `json_schema` with `strict: true` is the recommended operating mode; `json_object` is considered legacy and requires the string `json` in input. Field order follows schema order; `$ref` only as local `#` reference; `oneOf` carries no guarantee of "exactly one" semantics and `allOf` carries no guarantee of "all" semantics (`anyOf` is listed without qualification); unsupported keywords raise an error.
- Operations: Streaming is recommended; in non-streaming mode set `timeout` to over 30 minutes (Ark Go SDK always, even with streaming).
- Caching: Implicit caching via Responses API and Chat API, explicit caching via Responses API (prefix cache, session cache).
- Volcengine pricing (online inference, across entire 0–1024k **without tiered length pricing**, unlike doubao-seed-2.0-pro): ¥6.00 input, ¥1.20 cache hit, ¥30.00 output per million tokens, cache storage ¥0.017 per million tokens/hour. Batch inference: ¥3.00 / ¥1.20 / ¥15.00. Low-priority (Flex): ¥3.00 / ¥1.20 / ¥15.00 (implicit caching only). `doubao-seed-evolving` costs the same as Pro in online pricing.
- Multi-turn: Starting with doubao-seed-1.8, prior turns' `reasoning_content` should **remain** in history; the model decides internally how to utilize it; only on models prior to 251228 was the field actively stripped.

## Migration Notes
- **MIGRATING FROM doubao-seed-2.1-pro**: `thinking.type`, `reasoning_effort`/`reasoning.effort`, and `encrypted_content` return behavior are Ark-specific here (only `enabled|disabled`, `xhigh`/`max` → `high`, priority of `encrypted_content`) — identically named fields of other providers have different enums and defaults; re-map reasoning control against the target guide rather than adopting 1:1 or removing indiscriminately. Because CoT scaffolding and few-shot examples were deliberately eliminated here, "think step by step" instructions, examples, and explicit verification steps must be **re-introduced** as soon as the target is not an always-on reasoner. Reverse Ark's recommendation to put everything in the user prompt and cleanly separate roles again. Translate `response_format`/`json_schema` into the target's structured output format. Recalculate context (1024k for 260915, 256k for 260628), pricing, and the lower RPM ceiling.
- **MIGRATING TO doubao-seed-2.1-pro**: (1) Strip reasoning-forcing prompt instructions — the model reasons by default, and decomposition guidelines restrict it per documentation. (2) Set `reasoning_effort` explicitly; values inherited from providers supporting `xhigh`/`max` silently land on `high`, without error and without extra depth — run a fresh depth sweep rather than adopting defaults. (3) Fast paths require `thinking: {"type":"disabled"}` or `reasoning_effort: "minimal"`; adaptive `auto` does not exist here, so each route must decide explicitly. (4) Set `max_completion_tokens` or `max_output_tokens` — the 4k default truncates, and the reasoning chain counts toward it. (5) Slim down the system prompt and add goal, audience, and scenario instead. (6) Shift format specifications from the prompt into `response_format` and remove `frequency_penalty`/`presence_penalty`. (7) Pass `encrypted_content` through in tool chains or switch to the Responses API with `previous_response_id`. (8) Enable streaming or raise timeout above 30 minutes. (9) Adjust concurrency assumptions to 500 RPM / 1M TPM. (10) For international deployments, verify: Only Turbo is available from the 2.1 family there (see doubao-seed-2-1-turbo). (11) Pin snapshot: Ark specifies a 3–6 month lifecycle per version (model deprecations page); use `doubao-seed-evolving` only intentionally as a rolling pointer.
