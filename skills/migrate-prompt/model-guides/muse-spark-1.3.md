# Muse Spark 1.3

## Reasoning / Thinking
- Type: **always on, cannot be disabled**. `reasoning_effort: "none"` is explicitly rejected ("Disables reasoning. Not supported by Muse Wonder or Muse Spark: returns `HTTP 400`") — every zero-thinking fast path from a predecessor model must be mapped to `minimal` or `low`.
- Parameter name is protocol-dependent: `reasoning_effort` (Chat Completions) vs. `reasoning.effort` (Responses API). Levels: `minimal | low | medium | high | xhigh | max`. `max` exists in the Spark line exclusively for standard-tier `muse-spark-1.3`, not for `muse-spark-1.3-contributor`.
- **No published default value**: Without the parameter "the model still reasons at a model-determined level" — which level that is is not stated anywhere (unbelegt). Therefore, always set effort explicitly in the prompt contract.
- Chain of thought is private ("The model's chain of thought is private. The raw reasoning is not returned as readable text"); on Chat Completions `reasoning_content` is redacted to empty for external callers. Summaries exist only on the Responses API via `reasoning.summary` (`auto` ≈ one sentence / `concise` / `detailed`) — and even those are not guaranteed.
- Reasoning tokens count against `max_tokens` or `max_output_tokens` and are billed at the output rate; reported in `completion_tokens_details.reasoning_tokens` or `output_tokens_details.reasoning_tokens`. Recalculate token budgets for `xhigh`/`max`.
- Preserving reasoning across turns/tool loops: On the **Responses API** via `previous_response_id` or `include: ["reasoning.encrypted_content"]`, on the **Messages API** via Anthropic `thinking` replay (history managed client-side; `redacted_thinking` carries the encrypted blob and is returned). Only Chat Completions carries no reasoning across turns ("each turn reasons from scratch").
- Meta's own effort heuristic: high effort for "proofs and calculations, complex code generation, architecture trade-off analysis", `low` for direct responses with lower latency and cost. `logprobs` is not supported (HTTP 400).

## Prompting Style
- **`developer` role instead of `system`**: Meta explicitly recommends "prefer a `developer` message over the `system`" for tone, format, and standing rules. When migrating, relabel the system prompt layer accordingly, rather than merely copying it.
- **Effort is part of prompt design**, not just a cost control: For well-scoped tasks, Meta notes that `reasoning_effort=xhigh` can deliver an entire artifact in a single turn — multi-stage prompt choreography then becomes unnecessary.
- **Plan for or suppress clarifications**: The model "asks for input when needed", has "better calibration on what constitutes irreversible actions" according to the launch blog, and "confirms before taking consequential actions". For unattended runs, explicitly grant autonomy and supply defaults for underspecified requests.
- **Long, complex instructions are allowed**: 1.3 "follows complex, long-form instructions more reliably than earlier Muse Spark models" — precautionary breakdown into mini-prompts is not needed.
- **Tool descriptions carry the burden**: "Write clear, specific descriptions for the tool and for each parameter. The model uses them to decide when and how to call the tool." No prose explanations of tools in the system prompt.
- **Prompt ordering for caching**: "Put stable content first, such as system prompt, instructions, and examples, and put variable content last." Caching is active automatically without setup; ordering determines cache hit length.

## Strengths & Weaknesses (prompt-relevant)
- Positioning: According to model overview "the latest version" of the Muse Spark line and "Recommended for new work", "the default model in the code examples throughout these docs", available in Muse Code and the Meta Model API. Meta's most capable model according to the same page (as of 2026-10-13) is Muse Wonder (`muse-wonder-1.0`, preview), which accepts the same requests on the same endpoints.
- Strengths: "Trained for long-horizon, agentic workflows" — retains context and intermediate results, works "through messy or conflicting inputs", proactively corrects plan gaps, and processes multiple workflows in parallel. Natively multimodal perception (image, video, documents); images as base64 data URL or public URL directly in message content, including self-inspection of rendered results and error screenshots; computer use from plain-text goal plus screenshot without coordinates.
- Token economy: Compared to 1.2 according to Meta, approximately **20% fewer tool calls and 25% fewer tokens**, "takes fewer turns where not needed and is less verbose" — "be concise" instructions inherited from 1.2 are largely redundant.
- "Better awareness of its own capabilities and limitations" and fewer hallucinations — defensive "do not make things up" blocks can be slimmed down. Additionally "stronger adversarial robustness, with improved resistance to adversarial inputs and prompt injections"; injection hardening in the prompt remains beneficial, but is no longer the sole line of defense.
- Weaknesses: (Officially documented): **Audio**. "Audio understanding in Muse Spark 1.3 is currently not fully supported, and response quality for requests including audio content may be degraded. For audio, use Muse Spark 1.2, or Muse Voice Transcribe for dedicated speech-to-text."
  - Weaknesses: `tool_choice` accepts only `"auto"` — any forced tool selection (`required` or named function) ends in HTTP 400. Tool enforcement must be expressed linguistically in the prompt.
  - No published knowledge cutoff and no published output token limit (unbelegt). Benchmark comparisons in the launch blog are only presented as graphics, without figures in running text.

## Output & Format Conventions
- Context window **1,048,576 tokens**; input text, image, video, audio (limited, see above), and PDF, output text only. Maximum output tokens are not published (unbelegt).
- Structured Output: `response_format` with `"type": "json_schema"` (Chat Completions) or `text.format` (Responses API); "the model constrains token generation to produce only valid JSON matching your schema". `strict` is `false` by default; with `strict: true`, the root must be a simple object, every object must set `additionalProperties: false`, and `required` must list **all** keys. Recursive schemas are not supported. Limits (also apply to function tool `parameters`, exceeding → HTTP 400): depth 10, 5,000 properties, 120,000 characters total, 1,000 enum values (default, raisable per app); string enums with >250 values max 15,000 characters; schemas with >200,000 nodes after `$ref` expansion are rejected.
- Tool Calling: `parallel_tool_calls` is `true` by default (multiple calls per turn possible); `max_tool_calls` caps only built-in tools, not function tools; tool names must match `^[a-zA-Z0-9_.-]+$` with at most one dot. Even with `strict: true`, generated arguments are only schema-*guided* and "not guaranteed to validate against it" — continue validating server-side.
- Three protocols against the same models, same auth, and same price: Responses (`/v1/responses`, Meta's "recommended default for new work", only route for search grounding; reasoning preservation via encrypted replay or `previous_response_id`), Chat Completions (`/v1/chat/completions`, OpenAI format, no reasoning preservation across turns), Messages (`/v1/messages`, Anthropic format, history managed client-side, reasoning preservation via `thinking` replay; `thinking: {type: "disabled"}` → HTTP 400, `output_config.effort` passes only `low`–`xhigh`).
- Prices per 1M tokens: Standard $1.25 input / $0.15 cached input / $4.25 output; Contributor $0.10 / $0.002 / $0.20 — the Contributor tier trades price for "permission to use your prompts and completions to train future Meta models". No batch discount and no pricing tiers based on context length are documented.
- Prompt caching is automatic; hits appear in `usage.prompt_tokens_details.cached_tokens` (Chat Completions) or `usage.input_tokens_details.cached_tokens` (Responses). On the Responses API, `prompt_cache_retention: "24h"` requests extended retention up to 24 hours — only a hint, not a guarantee (earlier eviction under load is possible). Minimum prefix length for cacheable content is not documented (unbelegt).

## Migration Notes
- **MIGRATING FROM muse-spark-1.3**: Re-add conciseness, self-verification, and "do not fabricate" instructions if the target model lacks these characteristics natively; turn the `developer` message back to `system` if the target lacks a developer role; re-handle clarification behavior, because target models without "asks for input when needed" simply guess on underspecified prompts — write defaults into the prompt; remove Meta-specific fields (`reasoning.summary`, `include: ["reasoning.encrypted_content"]`, `previous_response_id`) and manage conversation state client-side; recalibrate effort ladder when the target can disable reasoning or uses different level names; re-evaluate audio paths that were routed to Muse Spark 1.2 or Muse Voice Transcribe due to 1.3's limitations against the target's capabilities.
- **MIGRATING TO muse-spark-1.3**: Remove `reasoning_effort: "none"` and any "do not think" equivalents (HTTP 400), mapping them to `minimal`/`low`; set effort explicitly rather than relying on an inherited default; remove `tool_choice: "required"` or named tool enforcement (only `"auto"` permitted, otherwise HTTP 400) and phrase the constraint linguistically instead; remove `logprobs` (HTTP 400); raise token budgets, as reasoning tokens consume `max_tokens`/`max_output_tokens`; migrate the system prompt into a `developer` message; remove verbosity and turn-saving instructions from 1.2 prompts; switch from Chat Completions to the Responses API (or in an Anthropic stack, the Messages API with `thinking` replay) if reasoning must be preserved across tool loops; search grounding requires the Responses API; reorder prompt so that static material is placed upfront; plan for `max` only if using the standard tier (Contributor does not support this level); API access involves changing base URL — from the OpenAI ecosystem to `api.meta.ai/v1` plus key swap, from the Anthropic ecosystem pointing the Messages API to `https://api.meta.ai`.
