# ERNIE 5.1 (文心 5.1)

## Reasoning / Thinking
- **No documented on/off toggle.** ernie-5.1 is listed neither on the `enable_thinking` nor on the `thinking` support list in the 深度思考 (Deep Thinking) documentation. The only ERNIE 5 model with `enable_thinking` is `ernie-5.0-thinking-preview` (where it defaults to `true`, can be disabled; the ernie-5.0 line is scheduled for retirement on 2026-10-29). For ernie-5.1, `enable_thinking: false` is **not documented** — do not rely on forcing a fast path without reasoning.
- **`thinking_budget` is listed**: Support list `ernie-5.1, ernie-5.0-thinking-preview（仅思考模式生效）, deepseek-v3.2-think`. Minimum 100; default is contradictory: the 深度思考 page specifies model-dependent chain-of-thought length, while the API reference (as of 2026-09-29) states 16384 (maximum = model-dependent length, not published for ernie-5.1). If the chain of thought exceeds the budget, it is truncated and the answer begins immediately — this is the only documented depth lever.
- **Counter-evidence**: The model list (CN 2026-10-08, intl 2026-09-07) states below its ERNIE Deep Thinking table that ERNIE thinking models do not support `thinking_budget`. ernie-5.1 is not listed in this table, but the note already contradicts the 深度思考 list regarding ernie-5.0-thinking-preview. Therefore, treat `thinking_budget` for ernie-5.1 as documented but unreliable, and verify behavior via testing.
- The note "仅思考模式生效" (effective only in thinking mode) in this list is attached **only** to ernie-5.0-thinking-preview, not to ernie-5.1 — the budget here applies without mode coupling. Baidu nowhere explicitly states that thinking is permanently active as a result (unbelegt).
- ernie-5.1 is missing from the 深度思考 table of the model list and therefore has **no published 思维链长度 (chain-of-thought length)**. The circulating 60k chain-of-thought figure belongs to the ernie-5.0 line (ernie-5.0, -thinking-preview, -thinking-latest), not to 5.1 (the ernie-5.0 line is scheduled for retirement on 2026-10-29).
- `thinking_strategy` (`short_think`, `chain_of_draft`) is documented exclusively for `deepseek-v3.2-think` — not available for ernie-5.1.
- The chain of thought returns in a dedicated `reasoning_content` field **alongside** `content` (in streaming as `delta.reasoning_content`). Parsers that only read `content` silently lose it.
- Interleaved Thinking (交错思考: passing `reasoning_content` back between tool calls) is not listed for ernie-5.1 (only deepseek-v3.2, ernie-5.0, ernie-5.0-thinking-preview).
- **Output ceiling**: `max_completion_tokens` is documented only for DeepSeek models according to the 上下文管理 (Context Management) docs, **not** for ernie-5.1. `max_tokens` according to the API reference (as of 2026-09-29) represents total output **inclusive** of chain of thought; the model list states the same for ERNIE thinking models. The older 上下文管理 page (2026-04-03) describes `max_tokens` as answer length excluding chain of thought. Because sources contradict each other, generously size `max_tokens` as a total ceiling (reasoning + answer).

## Prompting Style
- Baidu publishes **no model-specific prompting guide** for ernie-5.1. Authoritative references are limited to the API contract, a positioning sentence in the model list, and Baidu's release post from 2026-05-09; any styling statement beyond that is unbelegt.
- Official positioning: "文心系列最新模型，基础能力全面升级，在智能体、知识、推理、深度搜索等方面均有显著提升" — agents, knowledge, reasoning, deep search. The model row lists **no** other application areas — the enumeration 复杂语义理解 / 中文知识问答 / 文学创作 / 文档理解 / 中文数学题 in the same table belongs to the row `ernie-4.5-turbo-128k`, not to ernie-5.1, and must not be claimed for 5.1. In addition, the release post highlights creative writing (long-form narrative, specialized technical texts) as a core strength, close to Gemini 3.1 Pro according to internal evals (vendor statement). The 文学创作 enumeration in the model list nonetheless remains mapped to the ernie-4.5-turbo-128k row. Coding agentics is not specified for 5.1.
- **Do not force formatting via free-text schemas.** Strict Structured Outputs (`response_format: json_schema` with `strict: true`) do not list ernie-5.1. Reliable methods are Function Calling (demonstrably supported) or `response_format: json_object` **plus** an explicitly articulated schema in the prompt.
- Standard roles `system` / `user` / `assistant` / `tool` via the OpenAI-compatible endpoint `https://qianfan.baidubce.com/v2/chat/completions` (OpenAI SDK with `base_url=".../v2"` works). System prompt as first `system` message; Qianfan documents assistant prefill (对话前缀续写: `"prefix": true` on the last assistant message), but only for DeepSeek and Qwen3 models; ernie-5.1 is not on the support list, hence no prefill.
- Do not prompt research behavior manually: `web_search` is documented for the ERNIE 5.1 series (`enable`, `enable_citation`, `enable_trace`, `enable_status` each default `false`; `search_mode` default `auto`; `search_number`/`reference_number` default 10). Enforce citation requirements via `enable_citation` rather than requesting citations via prompt rules. Forced search is not supported: documentation notes that ERNIE models do not support 强制搜索 (`search_mode: required`).
- Keep tool descriptions concise: Function Calling costs roughly **300 additional tokens** due to internal prompt templating according to docs.

## Strengths & Weaknesses (prompt-relevant)
- Strengths: 128k context with 119k max input and up to **65,536 output tokens** — long source documents and long deliverables fit in the same call; Function Calling fully documented (`tools`, `tool_choice` `auto|none|required` or a specifically named tool object, parallel calls, return via `role: "tool"` + `tool_call_id`); integrated Baidu web search with citations; very low pricing (see below); officially positioned for agentics, knowledge, reasoning, and deep search; creative writing (release post, internal evals).
- Weaknesses / quirks: **no `json_schema` strict mode** — hard schema guarantees do not exist; **no prefix cache** (前缀缓存 lists only DeepSeek models), so long repeated system prompts are billed in full every time; **no batch pricing** (the batch cell in the pricing table is empty → no batch discount); low default rate limit of **RPM 60 / TPM 150,000**; not listed on the 视觉理解 (Visual Understanding) or 原生多模态 (Native Multimodal) support lists — treat as a **pure text model** despite the natively multimodal 5.0 line (unbelegt); listed on both Chinese and (since 2026-09-07) international English Qianfan model lists with identical limits (128k / 119k / [1, 65536], RPM 60 / TPM 150000); no published knowledge cutoff (unbelegt); no official recommendations for `temperature`/`top_p` (unbelegt).

## Output & Format Conventions
- Context window 128k, max input 119k, max output range `[1，65536]`; default flow control RPM = 60, TPM = 150,000.
- Response structure: `message.content`, alongside `reasoning_content` and optional `tool_calls`; streaming via `delta`.
- `response_format`: `text` (default), `json_object`, `json_schema` — the API reference only excludes the ERNIE-X1-Turbo series generally, but `json_schema` strict support is not listed for ernie-5.1. `json_object` is the reliable approach.
- `penalty_score` range 1.0–2.0, default 1.0 (the exclusion list in the API reference lists ERNIE-X1-Turbo and ERNIE 4.5 series, among others, and several DeepSeek models; ernie-5.1 is not on it); `seed` available for deterministic sampling.
- Pricing in CNY (元) per 1,000 tokens, tiered by **input length**: input ≤32k → 0.004 input / 0.018 output; 32k < input ≤128k → 0.006 input / 0.022 output. The tier also increases output price; align chunking decisions around the 32k boundary. There is no cache-hit price column for ernie-5.1, and the batch cell is empty (—).

## Migration Notes
- **MIGRATING FROM ernie-5.1**: `thinking_budget` has Qianfan-specific semantics here (minimum 100, no published chain-of-thought length for 5.1) — budget parameters from other vendors have different ranges and defaults; map to target `reasoning_effort`/`thinking` equivalents and recalibrate depth, as no chain-of-thought length is published for 5.1; replace `reasoning_content` parsing with the target's reasoning format; the platform `web_search` object including `enable_citation` is omitted — research and citation rules must be rebuilt as tools or prompt instructions; if the target supports true `json_schema` strict output, move the schema description articulated in the prompt there and remove it from text; the 32k pricing tier disappears — re-evaluate chunking strategy; verify quality on agent-, knowledge-, research-, and creative-writing-heavy prompts, which are the officially promoted dimensions (智能体, 知识, 推理, 深度搜索 according to model list; creative writing according to release post).
- **MIGRATING TO ernie-5.1**: **Remove** `enable_thinking` / `thinking: {type: ...}` — neither is documented for ernie-5.1; those previously disabling reasoning have no documented way to do so here and must constrain it via a small `thinking_budget` (minimum 100) instead (test effect, documentation is contradictory). Remove `thinking_strategy` (DeepSeek only). Re-size `max_tokens` as a total ceiling including chain of thought; remove `max_completion_tokens` (not documented for ernie-5.1). Remove `prefix: true` prefills and passing `reasoning_content` back between tool calls. Rebuild strict `json_schema` routes to `json_object` + schema in prompt or to Function Calling. Drop prefix/prompt caching assumptions: long system prompts are billed in full — keep them short or reduce context per call. Remove image inputs. An ERNIE-VL alternative target is no longer documented starting 2026-10-29: Baidu retires ERNIE 5.0 (including thinking variants) and ERNIE-4.5-Turbo-VL-128K/-32K on that date, citing DeepSeek-V4.1-Flash as replacement, not ernie-5.1. Size concurrency for RPM 60 / TPM 150,000. Replace custom web search tools with the native `web_search` object and set `enable_citation`, rather than requesting citations via prompt.
- **Lifecycle**: Baidu cites ernie-5.1 as the official replacement for ERNIE-X1.1 / X1.1-Preview, which was retired on 2026-09-29. In the retirement registry (as of 2026-09-24), ernie-5.1 itself has no scheduled retirement date.
