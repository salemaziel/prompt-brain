# Claude Sonnet 5.5

## Reasoning / Thinking
- Typ: **adaptiv, per Default an** — ein Request ohne `thinking`-Feld denkt (wie `{type: "adaptive"}`). `thinking: {type: "disabled"}` liefert **400** (`invalid_request_error` mit Verweis auf `between_tools`); `{type: "enabled", budget_tokens: N}` ebenfalls 400.
- Niedrigste Stufe ist `thinking: {type: "between_tools"}`: schaltet das Up-front-Thinking ab, nur bei effort `low`/`medium`/`high` erlaubt (bei `xhigh`/`max` → 400) und nimmt kein weiteres Feld an (`display`, `budget_tokens`, `block_binding` → 400). Ohne Tools enthält die Antwort dann nur Text; mit Tools kommen Progress-Notizen weiter als `thinking`-Blöcke mit Summary-Text.
- effort-Stufen `low | medium | high | xhigh | max`, Default `high`. Die Stufen sind **gegenüber Sonnet 5 neu kalibriert** — Einstellungen nicht übernehmen, sondern einen frischen Effort-Sweep fahren. Startwerte laut Doku: `high` allgemein; `medium` für gut spezifizierte agentische Coding-/Multistep-Tool-Aufgaben (`high` für härtere/längere); `medium` oder `low` für Chat und latenzkritische Arbeit; `xhigh`/`max` nur bei gemessenem Qualitätsgewinn.
- Ab `medium` denkt das Modell vor fast jeder Antwort kurz (auch bei einer Begrüßung); eine System-Prompt-Bitte, weniger zu denken, wirkt nicht zuverlässig — stattdessen effort senken. Bei `low` entfällt das Thinking bei den meisten einfachen Requests.
- `max_tokens` deckelt Thinking **plus** Antwort, auch wenn der Thinking-Inhalt nicht zurückkommt; für agentisches Coding 128000 setzen und streamen.
- Top-Level-effort zwischen Requests ändern invalidiert den Prompt-Cache. **Per-Message-Effort** (Beta `mid-conversation-output-config-2026-07-01`, auf Claude API und Google Cloud, nicht auf Amazon Bedrock) behält den Cache, braucht aber adaptives Thinking — mit `between_tools` liefert ein abweichender Per-Message-effort 400.
- `thinking.display` Default `"omitted"` (leere Blöcke); `"summarized"` für lesbare Zusammenfassungen.
- Nicht-Default-`temperature`/`top_p`/`top_k` → 400 auf jedem Request (`top_p`-Default 0.99, also auch `top_p: 1` → 400, ebenso `temperature` und `top_p` zusammen).
- **Thinking-Blöcke sind an Modell und Konversation gebunden**: Sonnet 5.5 liest Blöcke von Sonnet 5, Opus 4.8, Haiku 4.5 und älteren Modellen sowie (Claude API/Google Cloud) Haiku 5.5, nicht aber von Opus 5, Opus 5.5 oder Fable-/Mythos-Modellen; Sonnet-5.5-Blöcke liest nur Opus 5.5 (Claude API/Google Cloud). Ein Block nach einer Änderung an `system`, `tools` oder früheren Messages → 400 (Default für Accounts ab 31. August 2026); Blöcke sind zudem an den erzeugenden Account gebunden.

## Prompting-Stil
- Bestehende **Sonnet-5-Prompts laufen laut Anthropic ohne Änderung gut**; die Muster aus „Prompting Claude Sonnet 5" bleiben ein sinnvoller Start. Für die härteste Long-Horizon-Arbeit empfiehlt die Doku ein Opus-Modell.
- **Initiative steuern**: bei `low`/`medium` hält das Modell in agentischem Coding öfter vor Abschluss für Rückfragen an — erst effort erhöhen, sonst die Doku-Zeile „Keep working until everything the user asked for is done …" in den System-Prompt. Gegen ungefragte Tests/Docs/Hilfsdateien (auf jeder Stufe, mehr bei hohem effort) nur deren zweiten Absatz („When the work the user asked for is done and checked, stop and report …") ergänzen.
- Bei `xhigh`/`max` startet es nach Abschluss eigene Review-/Verifikationsrunden (ggf. mit Sub-Agenten) — Routinearbeit bei `high` oder darunter fahren oder die Doku-Zeile gegen Extra-Reviewrunden ergänzen. Bei offenen Anfragen („zeig, was du damit kannst") ausdrücklich sagen, wenn erst Ideen oder ein Plan gewünscht sind.
- **Tool-Auslösung im Prompt formulieren**: Forced `tool_choice` gibt es nicht mehr, also im Prompt sagen, wann ein Tool gilt. In Chat-/Wissensarbeit tool-hemmende Formulierungen („only use tools when strictly necessary", „minimize tool calls") streichen und bei vorhandenem Such-Tool anweisen, veränderliche Details aktiv nachzuschlagen.
- **JSON-Antworten auf Rechen-/Regelaufgaben**: bei `low`/`medium` antwortet das Modell oft ohne vorheriges Thinking. Mit Structured Outputs „Think the problem through before you answer." ans Ende des System-Prompts setzen oder `xhigh` nutzen; adaptives Thinking statt `between_tools` verwenden; ohne Structured Outputs den **letzten** JSON-Wert der Antwort parsen.
- Mit `between_tools` keine „nicht denken"-Anweisungen — sie machen interne XML-Tags im sichtbaren Output wahrscheinlicher. Manuelles Chain-of-Thought-Prompting durch Thinking ersetzen.
- **Progress-Updates**: Zeilen wie „hold all findings for the final response" entfernen und gewünschte Update-Punkte (Eröffnungszeile, Schluss-Recap) im System-Prompt beschreiben; für exakte Zwischen-Texte ein einfaches „Nachricht an User"-Tool im ersten Request deklarieren. Bleibt es zu still, nach etwa fünf stillen Tool-Schritten eine einmalige turn-scoped System-Message als Reminder anhängen (nach zwei, drei Versuchen aufhören).
- **Mid-Turn-User-Input**: nie in einen `tool_result`-Block legen (sonst als mögliche Prompt Injection gewertet); als Text-Block nach dem letzten `tool_result` derselben User-Message anhängen, Harness-Hinweise getrennt als Mid-Conversation-System-Message; keine eigenen Token-Countdowns nach Tool-Results in interaktiven Sessions.
- **Verifikation**: bei `low` meldet es Änderungen mitunter ohne echten Test-/Build-Lauf als fertig — die Doku-Verifikationsregel („run a real check that exercises the change before reporting it done …") ergänzen.
- **Reasoning nicht im Antworttext anfordern**: Prompts, Skills und Tool-Beschreibungen, die das Modell sein Thinking/Reasoning ausschreiben lassen — wörtlich oder in festem Format (`<thinking>`-, `<reasoning>`- oder Scratchpad-Abschnitt vor der Antwort, `reasoning`-/`thinking`-/`trace`-Feld in JSON-Output oder Tool-Input, Reasoning-Log, Reasoning „verbatim"/„in full") —, können mit `stop_reason: "refusal"` und `stop_details.category: "reasoning_extraction"` abgelehnt werden. Stattdessen eine kurze Begründung, die Belege oder eine Zusammenfassung der ausgeführten Schritte anfordern; wird das Reasoning selbst gebraucht, Thinking anlassen und die Thinking-Blöcke mit `display: "summarized"` lesen. Die Kategorie hat kein Fallback-Modell (Prompt ändern statt erneut senden), und eine Ablehnung vor jedem Output wird abgerechnet.

## Stärken & Schwächen (prompt-relevant)
- Stärken: laut Anthropic die beste Kombination aus Speed und Intelligenz im aktuellen Lineup (Latenz „Fast"); prüft in agentischem Coding seine Arbeit in der Regel selbst; liest dichte Charts und technische Zeichnungen mit Crop-/Zoom-/Code-Tools deutlich genauer (bei Charts wirken Tools stärker als mehr effort, bei Zeichnungen erst ab `high`).
- Schwächen/Eigenheiten: Rückfragen vor Abschluss bei `low`/`medium`; ungefragte Ergänzungen und Extra-Reviewrunden bei hohem effort; antwortet in Chat-/Wissensarbeit mitunter aus dem Trainingswissen statt zu suchen; ruft gelegentlich Tools mit falscher Groß-/Kleinschreibung oder leicht abweichendem Parameternamen auf (Harness tolerant machen oder `is_error: true` mit exaktem Namen zurückgeben); wertet echte Mid-Turn-Nachrichten unter Umständen als Injection.
- Safety-Klassifikatoren mit fünf `stop_details`-Kategorien: `cyber`, `bio`, `frontier_llm`, `reasoning_extraction`, `general_harms` (letztere kann auch harmlose Arbeit treffen). Server-side Fallback (`fallbacks: "default"`, Beta, nur Claude API) wiederholt `cyber`/`frontier_llm` auf Sonnet 5, nicht aber `bio`, `reasoning_extraction`, `general_harms`.

## Output- & Format-Konventionen
- 1M Kontextfenster, 128K Output-Tokens (synchron); Message Batches API bis 300K mit Beta-Header `output-300k-2026-03-24`.
- Preise pro MTok: $2 Input / $10 Output, 5m-Cache-Write $2.50, 1h-Cache-Write $4, Cache-Read $0.10 (halber Sonnet-5-Satz); Batch −50 %. Minimal cachebarer Prompt 512 Tokens (Sonnet 5: 1.024).
- Tokenizer wie Sonnet 5 (gegenüber Sonnet 4.6/Haiku 4.5 rund 30 % mehr Tokens). Hochauflösende Bilder bis 2576 px lange Kante bzw. 4.784 Visual-Tokens pro Bild.
- **Forced Tool Use → 400**: `tool_choice` `{"type": "any"}`/`{"type": "tool", ...}` werden abgelehnt (auch am Token-Counting-Endpunkt); `auto` und `none` gehen. Für schema-valide Tool-Inputs `auto` plus `strict: true` oder Structured Outputs; auf Amazon Bedrock sind Structured Outputs/Strict für Sonnet 5.5 nicht verfügbar → `auto` ohne `strict`, Input im Code validieren.
- **Text zwischen Tool-Calls** kommt (ab ein, zwei Sätzen) als Progress-Update-`thinking`-Block — beim Default-`display` leer. Content-Blöcke nach `type` lesen, Thinking-Blöcke unverändert zurückgeben; zum Anzeigen `display: "updates"` (Beta `thinking-display-updates-2026-08-18`) oder `"summarized"` setzen, bei `between_tools` kommt der Text ohnehin.
- Kein Assistant-Prefill (400) — Structured Outputs bzw. Anweisungen im Prompt; `output_format` ist deprecated → `output_config.format`.
- Computer Use auf Claude API und Google Cloud nur über `computer_toolset_20260801` (`computer_20251124` → 400; auf Bedrock weiter erlaubt); `computer_20250124` nirgends.
- Model IDs: `claude-sonnet-5-5` (Claude API, Google Cloud, Microsoft Foundry, Claude Platform on AWS), Amazon Bedrock `anthropic.claude-sonnet-5-5`. Reliable Knowledge Cutoff Jun 2026.

## Migrations-Hinweise
- **ZU Sonnet 5.5 (von Sonnet 5)** — die sechs Punkte der Doku: (1) `thinking: disabled` → `between_tools` bei effort `high` oder darunter; (2) `tool_choice` `any`/`tool` → `auto` plus Strict Tool Use; (3) Konversation append-only halten, Instruktions-/Tool-Änderungen per Mid-Conversation-System-Message statt Edit; (4) `computer_20251124` auf Claude API/Google Cloud → Toolset; (5) Advisor-Tool nicht mit Opus 4.8, 4.7, 4.6, Sonnet 5, Sonnet 4.6 oder Haiku 5.5 als Advisor (400); (6) Text zwischen Tool-Calls aus Thinking-Blöcken lesen (`display` setzen). Dazu Effort-Sweep neu fahren und Refusal-Handling ergänzen.
- **ZU Sonnet 5.5 (von Sonnet 4.6 oder älter)**: zusätzlich damit rechnen, dass Requests ohne `thinking`-Feld jetzt denken (`max_tokens` prüfen); `budget_tokens` durch effort ersetzen (keine feste Umrechnung, zwei, drei Stufen evaluieren); Sampling-Parameter entfernen; `display: "summarized"` setzen, falls Thinking angezeigt wird; Tokens neu zählen (~30 % mehr) und Bild-Token-Budgets anpassen; `xhigh` ist neu.
- **Von Sonnet 4.5 oder älter / Haiku 4.5**: außerdem Prefills ersetzen, Tool-Input mit JSON-Parser lesen, effort explizit setzen, Context-Window-Beta-Header und `interleaved-thinking-2025-05-14` entfernen, `fine-grained-tool-streaming-2025-05-14` durch `eager_input_streaming: true` pro Tool ersetzen; von Haiku 4.5 Kosten neu baselinen (höherer Preis, Cache-Minimum fällt von 4.096 auf 512).
- **VON Sonnet 5.5 weg**: `between_tools` akzeptiert nur Sonnet 5.5 — auf den Abschalt-Mechanismus des Ziel-Guides umstellen (Sonnet 5: `disabled`). Forced Tool Use funktioniert anderswo mit adaptivem Thinking wieder (nicht mit manuellem Extended Thinking), außer auf Opus 5.5, Fable 5.1 und Mythos 5.1. Außer Opus 5.5 liest kein Modell Sonnet-5.5-Thinking-Blöcke → Reasoning-Kontinuität geht beim Wechsel verloren. Per-Message-Effort und Mid-Conversation-System-Messages fehlen auf Sonnet 5 (dort Top-Level-`system`). Die Anweisungen gegen Reasoning im Antworttext beibehalten, wenn das Ziel ebenfalls `reasoning_extraction` kennt.
- Lifecycle: Status *Active (latest)*, Release 28. September 2026, Retirement nicht vor dem 28. September 2027 (Anthropic-Plattformen; Bedrock/Google Cloud setzen eigene Daten).
