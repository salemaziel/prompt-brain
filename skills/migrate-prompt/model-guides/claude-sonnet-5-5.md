# Claude Sonnet 5.5

## Reasoning / Thinking
- Type: **adaptive, on by default** — a request without a `thinking` field engages in thinking (equivalent to `{type: "adaptive"}`). `thinking: {type: "disabled"}` returns **400** (`invalid_request_error` pointing to `between_tools`); `{type: "enabled", budget_tokens: N}` also returns 400.
- Lowest level is `thinking: {type: "between_tools"}`: disables up-front thinking, allowed only at effort `low`/`medium`/`high` (at `xhigh`/`max` → 400) and accepts no other fields (`display`, `budget_tokens`, `block_binding` → 400). Without tools, the response then contains only text; with tools, progress notes continue to appear as `thinking` blocks with summary text.
- Effort levels: `low | medium | high | xhigh | max`, default `high`. Effort tiers are **recalibrated compared to Sonnet 5** — do not carry over settings; run a fresh effort sweep instead. Starting recommendations according to docs: `high` generally; `medium` for well-specified agentic coding / multi-step tool tasks (`high` for harder/longer tasks); `medium` or `low` for chat and latency-critical work; `xhigh`/`max` only with measured quality gains.
- Starting at `medium`, the model thinks briefly before almost every answer (even greetings); requesting in the system prompt to think less is ineffective — lower effort instead. At `low`, thinking is skipped for most simple requests.
- `max_tokens` caps thinking **plus** response, even if thinking content is not returned; set 128000 and stream for agentic coding.
- Modifying top-level effort between requests invalidates the prompt cache. **Per-message effort** (beta `mid-conversation-output-config-2026-07-01`, on Claude API and Google Cloud, not on Amazon Bedrock) preserves the cache, but requires adaptive thinking — with `between_tools`, a differing per-message effort returns 400.
- `thinking.display` default `"omitted"` (empty blocks); `"summarized"` for readable summaries.
- Non-default `temperature`/`top_p`/`top_k` → 400 on every request (`top_p` default 0.99, so `top_p: 1` → 400 as well, as does `temperature` and `top_p` specified together).
- **Thinking blocks are bound to model and conversation**: Sonnet 5.5 reads blocks from Sonnet 5, Opus 4.8, Haiku 4.5, and older models, as well as (Claude API/Google Cloud) Haiku 5.5, but not from Opus 5, Opus 5.5, or Fable/Mythos models; Sonnet 5.5 blocks are read only by Opus 5.5 (Claude API/Google Cloud). A block submitted after a change to `system`, `tools`, or earlier messages → 400 (default for accounts created on or after August 31, 2026); blocks are additionally bound to the generating account.

## Prompting Style
- Existing **Sonnet 5 prompts run well without changes according to Anthropic**; patterns from "Prompting Claude Sonnet 5" remain a practical starting point. For the most demanding long-horizon work, documentation recommends an Opus model.
- **Steer initiative**: at `low`/`medium`, the model pauses more often for clarifying questions before completion in agentic coding — raise effort first, or add the doc line "Keep working until everything the user asked for is done …" to the system prompt. Against unprompted tests/docs/helper files (at any tier, more so at high effort), append only its second paragraph ("When the work the user asked for is done and checked, stop and report …").
- At `xhigh`/`max`, it initiates its own review/verification rounds upon completion (potentially with subagents) — run routine work at `high` or below, or add doc guidelines against extra review rounds. In open-ended requests ("show what you can do with this"), explicitly specify if only initial ideas or a plan are wanted.
- **Formulate tool triggering in prompt**: Forced `tool_choice` is no longer supported, so specify in the prompt when a tool applies. In chat/knowledge work, remove tool-inhibiting phrasing ("only use tools when strictly necessary", "minimize tool calls") and instruct the model to look up changing details actively when a search tool is available.
- **JSON responses on math/rule-based tasks**: at `low`/`medium`, the model often answers without preliminary thinking. With Structured Outputs, add "Think the problem through before you answer." to the end of the system prompt or use `xhigh`; use adaptive thinking rather than `between_tools`; without Structured Outputs, parse the **final** JSON value of the response.
- With `between_tools`, do not include "do not think" instructions — they increase the likelihood of internal XML tags leaking into visible output. Replace manual chain-of-thought prompting with thinking.
- **Progress updates**: remove lines such as "hold all findings for the final response" and describe desired update points (opening line, closing recap) in the system prompt; declare a simple "message to user" tool in the first request for exact intermediate texts. If the model remains too quiet, append a single-turn-scoped system message reminder after about five silent tool steps (stop after two or three attempts).
- **Mid-turn user input**: never place in a `tool_result` block (risk of being treated as prompt injection); append as a text block after the last `tool_result` of the same user message; separate harness instructions into a mid-conversation system message; avoid token countdowns after tool results in interactive sessions.
- **Verification**: at `low`, it sometimes marks changes as complete without running a real test/build — add the doc verification rule ("run a real check that exercises the change before reporting it done …").
- **Do not request reasoning in the response text**: prompts, skills, and tool descriptions that prompt the model to write out thinking/reasoning — verbatim or in a fixed format (`<thinking>`, `<reasoning>`, or scratchpad section before the answer, `reasoning`/`thinking`/`trace` field in JSON output or tool input, reasoning log, reasoning "verbatim"/"in full") — can be rejected with `stop_reason: "refusal"` and `stop_details.category: "reasoning_extraction"`. Instead, request a brief explanation, evidence, or a summary of executed steps; if reasoning itself is needed, keep thinking enabled and read thinking blocks with `display: "summarized"`. This category has no fallback model (modify the prompt rather than resending), and refusals occurring before any output are billed.

## Strengths & Weaknesses (prompt-relevant)
- Strengths: according to Anthropic, the best balance of speed and intelligence in the current lineup (latency "Fast"); in agentic coding, typically self-checks work; reads dense charts and technical diagrams much more accurately using crop/zoom/code tools (for charts, tools help more than extra effort; for diagrams, gains emerge starting at `high`).
- Weaknesses / quirks: clarifying questions prior to completion at `low`/`medium`; unprompted additions and extra review rounds at high effort; sometimes answers from training data instead of searching in chat/knowledge work; occasionally calls tools with wrong casing or slightly differing parameter names (make harness tolerant or return `is_error: true` with exact name); may interpret legitimate mid-turn messages as injection.
- Safety classifiers with five `stop_details` categories: `cyber`, `bio`, `frontier_llm`, `reasoning_extraction`, `general_harms` (the latter can also affect benign tasks). Server-side fallback (`fallbacks: "default"`, beta, Claude API only) retries `cyber`/`frontier_llm` on Sonnet 5, but not `bio`, `reasoning_extraction`, or `general_harms`.

## Output & Format Conventions
- 1M context window, 128K output tokens (synchronous); Message Batches API up to 300K with beta header `output-300k-2026-03-24`.
- Pricing per MTok: $2 input / $10 output, 5m cache write $2.50, 1h cache write $4, cache read $0.10 (half of Sonnet 5 rate); batch −50%. Minimum cacheable prompt 512 tokens (Sonnet 5: 1,024).
- Tokenizer same as Sonnet 5 (roughly 30% more tokens compared to Sonnet 4.6 / Haiku 4.5). High-resolution images up to 2,576 px long edge or 4,784 visual tokens per image.
- **Forced tool use → 400**: `tool_choice` `{"type": "any"}` / `{"type": "tool", ...}` are rejected (including at the token counting endpoint); `auto` and `none` work. For schema-valid tool inputs, use `auto` plus `strict: true` or Structured Outputs; on Amazon Bedrock, Structured Outputs / strict mode are not available for Sonnet 5.5 → use `auto` without `strict` and validate input in code.
- **Text between tool calls** arrives (beyond one or two sentences) as a progress update `thinking` block — empty under default `display`. Read content blocks by `type`, return thinking blocks unmodified; to display text, set `display: "updates"` (beta `thinking-display-updates-2026-08-18`) or `"summarized"`; with `between_tools`, text returns normally.
- No assistant prefill (400) — use Structured Outputs or prompt instructions; `output_format` is deprecated → `output_config.format`.
- Computer Use on Claude API and Google Cloud only via `computer_toolset_20260801` (`computer_20251124` → 400; still permitted on Bedrock); `computer_20250124` not accepted anywhere.
- Model IDs: `claude-sonnet-5-5` (Claude API, Google Cloud, Microsoft Foundry, Claude Platform on AWS), Amazon Bedrock `anthropic.claude-sonnet-5-5`. Reliable knowledge cutoff Jun 2026.

## Migration Notes
- **MIGRATING TO claude-sonnet-5-5**:
  - Specifically **from claude-sonnet-5** — the six points from docs: (1) `thinking: disabled` → `between_tools` at effort `high` or below; (2) `tool_choice` `any`/`tool` → `auto` plus Strict Tool Use; (3) keep conversation append-only, change instructions/tools via mid-conversation system messages instead of editing; (4) `computer_20251124` on Claude API/Google Cloud → toolset; (5) advisor tool not compatible with Opus 4.8, 4.7, 4.6, Sonnet 5, Sonnet 4.6, or Haiku 5.5 as advisor (400); (6) read text between tool calls from thinking blocks (set `display`). Additionally, rerun effort sweep and add refusal handling.
  - Specifically **from claude-sonnet-4-6 or older**: additionally anticipate that requests without a `thinking` field now think (verify `max_tokens`); replace `budget_tokens` with effort (no fixed conversion; evaluate two or three levels); remove sampling parameters; set `display: "summarized"` if displaying thinking; recount tokens (~30% more) and adjust image token budgets; `xhigh` is newly available.
  - Specifically **from Sonnet 4.5 or older / Haiku 4.5**: additionally replace prefills, parse tool input with JSON parser, set effort explicitly, remove context window beta headers and `interleaved-thinking-2025-05-14`, replace `fine-grained-tool-streaming-2025-05-14` with `eager_input_streaming: true` per tool; from Haiku 4.5 re-baseline costs (higher price, cache minimum drops from 4,096 to 512).
- **MIGRATING FROM claude-sonnet-5-5**: `between_tools` is accepted only by Sonnet 5.5 — convert to the disabling mechanism in the target guide (Sonnet 5: `disabled`). Forced tool use works elsewhere with adaptive thinking again (not with manual extended thinking), except on Opus 5.5, Fable 5.1, and Mythos 5.1. No model other than Opus 5.5 reads Sonnet 5.5 thinking blocks → reasoning continuity is lost on switch. Per-message effort and mid-conversation system messages are absent on Sonnet 5 (use top-level `system` there). Retain instructions against reasoning in response text if the target also recognizes `reasoning_extraction`.
- Lifecycle: Status *Active (latest)*, release September 28, 2026, retirement not before September 28, 2027 (Anthropic platforms; Bedrock/Google Cloud set own dates).
